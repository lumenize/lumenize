# Mesh API

All mesh node types — [LumenizeDO](./lumenize-do), [LumenizeWorker](./lumenize-worker), and [LumenizeClient](./lumenize-client) — share a common API for mesh communication.

## Interface: `LmzApi`

Every mesh node has access to `this.lmz`:

### Identity & Context

```typescript @check-example('packages/mesh/src/lmz-api.ts')
// this.lmz
readonly bindingName?: string;
readonly instanceName?: string;
readonly type: NodeType;
readonly callContext: CallContext;
```

| `type` | `instanceName` |
|--------|----------------|
| `'LumenizeDO'` | Named instance (e.g., `'document-123'`) |
| `'LumenizeWorker'` | Always `undefined` |
| `'LumenizeClient'` | Client identifier (e.g., `'alice.tab1'`) |

### `call()` — Fire-and-Forget Call

The primary method for mesh communication. Returns immediately while work executes asynchronously.

```typescript @check-example('packages/mesh/src/lmz-api.ts')
// this.lmz.call()
call<T = any>(
  calleeBindingName: string,
  calleeInstanceName: string | undefined,
  remoteContinuation: Continuation<T>,
  handlerContinuation?: AnyContinuation,
  options?: CallOptions
): void;
```

For `call()` patterns including fire-and-forget, response handlers, chaining, and error handling, see [Making Calls](./calls).

### `broadcast()` — One Continuation, Many Targets

Sends one continuation to every target — one `call()` per target, from this node, at any number of targets. Every node type carries it, clients included.

```typescript @check-example('packages/mesh/src/lmz-api.ts')
// this.lmz.broadcast()
broadcast<T = any>(
  targets: BroadcastTarget[],
  remoteContinuation: Continuation<T>,
  options?: BroadcastOptions
): void;
```

For its options, failure handling and limits, see [Broadcast](./broadcast).

### Awaiting a result

`call()` never returns a value — it fires-and-forgets or delivers the outcome to a handler. The one place you can `await` a cross-node call is the **client-only** `callAsync` (a DO/Worker can't hold a Promise across hibernation, so it uses `call()` + a handler instead) — see [LumenizeClient § Awaiting a result](./lumenize-client#awaiting-a-result--callasync-client-only). The single awaited Workers-RPC hop that `call()` uses internally is private framework transport, not a public API.

### `CallOptions`

```typescript @check-example('packages/mesh/src/types.ts')
interface CallOptions {
  newChain?: boolean; // Start fresh call chain (this node becomes origin)
  state?: Record<string, unknown>; // Initial or merged state for the call
  // ...
  onSent?: (callId: string) => void;
  // ...
  onErrorOnly?: boolean;
}
```

When `newChain` is false (the default) and the `state` option is provided, it is merged with any inherited state from the current [call context](#interface-callcontext) (overlapping properties are overwritten). When `newChain` is true, the `state` option becomes the initial state for the new chain.

`onSent` is invoked synchronously with the generated `callId` immediately before the call message is sent (or queued, when disconnected). Useful for correlating an outbound call with later inbound frames — e.g. tracing markers or custom Gateway-emitted WebSocket frames — without exposing the client's internal pending-call map.

`onErrorOnly` applies only to the 4-arg `this.lmz.call(callee, instance, remote, handler, opts)` form: when `true`, the handler chain is invoked only on remote rejection; successful results are dropped without dispatch. Useful for fire-and-forget paths that want structured error handling (retry, escalation, cleanup) without paying the per-call success-path dispatch cost — `broadcast()` adds it to every call whenever you pass an `onResult`.

## Interface: `CallContext`

Available via `this.lmz.callContext` during any incoming mesh call — including `onBeforeCall()`, `@mesh()` guard functions, the handler method itself, and any code any of those call:

```typescript @check-example('packages/mesh/src/types.ts')
interface CallContext {
  // Immutable — full call path: [origin, hop1, hop2, ..., caller]
  callChain: NodeIdentity[];

  // Immutable — verified claims from origin's JWT (if authenticated)
  originAuth?: OriginAuth;

  // Immutable — HTTP facts of the originating upgrade, stamped by the Gateway (client-originated
  // chains only). Tamper-evident like originAuth: NOT in callChain[0] (which the client partly
  // authors) and NOT in state (which any hop may mutate). Server-side only: never sent to a client.
  originRequest?: OriginRequest;

  // ...

  callee?: NodeIdentity;

  // Mutable — can be modified by onBeforeCall or any handler along the way
  state: Record<string, unknown>;
}
```

`callee` is the one field that does **not** ride through: it is PER-HOP, stamped by the framework with the node this hop was addressed to, and each hop overwrites it. A handler reads it to learn WHICH target answered — a fan-out gives every target the same handler chain, so the reply is the only thing that differs, and a reply is authored by the far side. ⚠️ On a mesh fire-back it is the callee's self-reported identity; on the request leg and at the receiving node it is the address used, which nobody else can write.

```typescript @check-example('packages/mesh/src/types.ts')
interface NodeIdentity {
  type: 'LumenizeDO' | 'LumenizeWorker' | 'LumenizeClient';
  bindingName: string;
  instanceName?: string; // undefined for Workers
}
```

**Property summary:**
- `callChain` — Full call path from origin to immediate caller. **Immutable** — grows at each hop (managed by framework).
- `originAuth` — Verified JWT claims from original caller. **Immutable**. Only set for authenticated LumenizeClient origins.
- `originRequest` — HTTP facts of the WebSocket upgrade that started the chain: the origin's IP address, `User-Agent`, `Accept-Language`, and Cloudflare's `cf` location fields. **Immutable**. Only set for LumenizeClient origins, and **server-side only**: the Gateway never forwards it to a client, and a LumenizeClient types `this.lmz.callContext` as `Omit<CallContext, 'originRequest'>`, so reading it there fails to compile.
- `state` — Hook data. **Mutable** — starts as `{}`, often populated in `onBeforeCall()` but can be set or modified anywhere in this call context.

**Accessing identity:**
- Origin (who started the chain): `callChain[0]`
- Immediate caller: `callChain.at(-1)`
- This node's identity: `this.lmz.bindingName`, `this.lmz.instanceName`

For context propagation and persistence patterns, see [Managing Context](./managing-context).

## Decorator: `@mesh()`

Marks a **member** as a mesh entry point — a method, or a getter. A chain arriving off the wire must open on one: its first operation names a marked member, and that is where the guard runs. Everything after that runs on whatever the member handed back — unchecked by the entry rule, though the walk rules still apply (see `requireMeshDecorator` in [Managing Context](./managing-context)). A member without `@mesh()` cannot be reached from outside the node, and that absence is the security boundary — not visibility, which the runtime does not see.

```typescript @skip-check-approved('conceptual')
@mesh()                       // Basic entry point
@mesh(guardFunction)          // With access control guard
```

**Use a getter for a GATE** — an entry that returns a capability surface and does nothing else — and a method for everything else, whatever its arity. A gate reads as the thing it hands back (`ctn<T>().settings.read()`), which is how the caller thinks of it. The pair below is the asymmetry readers get wrong: the marked one is reachable from the wire, the unmarked one is not, and the absence of the decorator is what does the second.

```typescript @check-example('packages/mesh/test/for-docs/security/gate-pair-do.ts')
  // A GETTER gate. The guard runs at the ENTRY op — read off the descriptor, before the getter
  // body is invoked — and the body then picks what to hand back.
  @mesh(requireAdmin) get settings(): Settings { return new Settings(this); }

  // The same capability, UNMARKED, so it is unreachable from the wire. An unmarked getter is
  // refused WITHOUT running: the check reads the property's descriptor, never the property.
  get settingsForResults(): Settings { return this.#openResults(); }
```

⚠️ A getter entry runs code behind a property read, and nothing at the call site says so. Keep one side-effect-free, synchronous, cheap and idempotent — a gate returns a surface and does nothing else.

`accessor` and fields are deliberately **not** entry kinds, and both fail to compile under `@mesh()`. A chain can only `get` and `apply`, so a marked `accessor` would be a marked getter with a setter no caller can reach; a field would hand its object over as-is, with no code in between to narrow it.

**Guard signature:**
```typescript @skip-check-approved('conceptual')
(instance: T) => void
// Throw to deny access. Access context via instance.lmz.callContext.
```

For guard patterns and access control, see [Security](./security#access-control).

## Hook: `onBeforeCall()`

Override for class-wide access control that runs before every mesh call:

```typescript @skip-check-approved('conceptual')
onBeforeCall(): void
// Call super.onBeforeCall() for default behavior
// Access context via this.lmz.callContext
// Throw to reject the call
```

| Level | Mechanism | Purpose |
|-------|-----------|---------|
| Class-wide | `onBeforeCall()` | WHO can call (authentication) |
| Method-level | `@mesh(guard)` | Fine-grained permissions |

For the complete security model, see [Security](./security#access-control).

## Method: `this.ctn<T>()`

Creates type-safe continuations for mesh calls:

```typescript @skip-check-approved('conceptual')
// Remote continuation — what to call on another node
this.ctn<OtherDO>().someMethod(arg1, arg2)

// Local continuation — what to call on this instance
this.ctn().handleResult(this.ctn().$result)
```

The `$result` placeholder gets replaced with the actual result (or `Error`) when the continuation executes.

For operation chains, nesting, and context preservation, see [Continuations](./continuations).
