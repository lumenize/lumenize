# Stored values merge-patch small and exact

**Status:** Pass 1 and its success criteria written 2026-10-14; `/review-task` Stage 1 ran twice and is resolved; Pass 2 written 2026-10-14; Stage 2 ran 2026-10-14 and is resolved. Ready for `/build-task`. A pre-alpha must-have that gates ⑥ the wipe ([nebula-pre-alpha.md](nebula-pre-alpha.md)).

## Objective

**A change to one property of an object, to one entry of a Map or Set whose keys are all strings or all numbers, or appending to or removing from a long array of distinct strings, patches with RFC 7396 to the size of that change, and applying any patch gives back the value that was encoded: every property and entry, and every Map's, Set's and array's order.** A plain object's key order is the one thing a patch does not keep, and § *Design intent* rules 1–3 say which collections still change as a whole.

| Value | Encoded today | Encoded after this task |
|---|---|---|
| `new Map([['pro', 25]])` | `{"$type":"map","entries":[["pro",25]]}` | `{"$type":"map","object":{"pro":25}}` |
| `new Set(['a', 'b'])` | `{"$type":"set","values":["a","b"]}` | `{"$type":"set","object":{"a":1,"b":1}}` |
| `new Map([['42', 1]])`, an integer-like key | `{"$type":"map","entries":[["42",1]]}` | `{"$type":"map","object":{"$42":1}}` |
| `new Map([[2026, 'a'], [1.5, 'b']])`, number keys | `{"$type":"map","entries":[[2026,"a"],[1.5,"b"]]}` | `{"$type":"map","keyType":"number","object":{"$2026":"a","1.5":"b"}}` |
| 500 distinct ids, such as a to-many `members` list | `["0b6c0000-…","0b6c0001-…",…]` | `{"$type":"array","object":{"0b6c0000-…":1,"0b6c0001-…":1,…}}` |
| `['red', 'green', 'blue']`, short | `["red","green","blue"]` | unchanged: its plain form is under the 256-byte threshold |
| an object shared by `owner` and `reviewer` | `{"$ref":0}` at both, the object hoisted to `meta.aliases["0"]` | the object in full at `owner`, `{"$ref":"#/owner"}` at `reviewer` |
| `{ b: null }` | `{"json":{"b":null},"meta":{}}` | `{"b":{"$type":"null"}}` |
| `new Uint8Array([1, 2, 3])` | `{"$type":"arraybuffer","subtype":"Uint8Array","data":[1,2,3]}` | `{"$type":"arraybuffer","subtype":"Uint8Array","base64":"AQID"}` |
| `{ title: 'Ship it' }`, the whole encoding | `{"json":{"title":"Ship it"},"meta":{}}` | `{"title":"Ship it"}` |

## Context

**Adding one entry to a Map sends the whole Map.** `@lumenize/structured-clone` writes a Map as one `entries` array, a Set as one `values` array, and an id list as one plain array, and RFC 7396 replaces an array whole. The format was designed for merge patch: [archive/structured-clone-object-based-wire-format.md](archive/structured-clone-object-based-wire-format.md) § *D2: Permissions stay nested in-memory* decided that Maps travel as nested objects. Its experiment measured that shape with plain objects standing in for Maps, and `experiments/structured-clone-object-format/RESULTS.md` § *Recommendation* left the encoding of special types to the implementation, which kept the old tuple format's arrays. Its Map test checks only that a patch round-trips, and the test beside it is named for a small patch but never measures one. Nothing has sent a patch yet, so production is unaffected.

**This surfaced on 2026-10-14**, while weighing JSON Merge Patch as the way to deliver a resource change through MCP Events ([backlog.md](backlog.md) § *Lumenize Mesh*, the MCP Events row). Probing the encoder for that found more: shared objects keyed by a counter, a `null` a patch reads as a delete, a `__proto__` key `diff` drops, a request's body copied raw, a sparse array's hole written as `null`, and binary written as a number array.

**The wipe is the last point at which all of it can change for free.** Four places store this encoding: `Snapshots.value`, which holds every resource version; the operation chains in `__lmz_alarms` (`packages/mesh/src/alarms.ts`); `Subscriptions.query`; and `Subscriptions.topic`, a query hash computed from it. [ADR-004](../docs/adr/004-snodgrass-temporal-resources.md) never rewrites a resource version. Most of the changes below could be decoded beside the old form, but every version stored before them would keep patching large or losing its nulls. One cannot be decoded beside it at all: once the wrapper goes, a user's own `{ json, meta }` object reads exactly like an old encoding. The wire closes too: every generated app bundles the codec (`apps/nebula/container/Dockerfile` copies `packages/structured-clone/src` into the build image), and a `.dev` app runs its last landed build until it is rebuilt ([ADR-024](../docs/adr/024-two-versions-keep-an-app-in-step.md)), so after the wipe a change to any encoded form breaks every app built before it. Larry, 2026-10-14: merge-patch sync can wait until after pre-alpha, but the format it will patch cannot.

The goals below say what is wrong today, measured, and § *Design intent* says what the encoder and `diff` do instead.

## Goals

Each goal says how today's code misses it, except goal 4, which goal 1 creates. Every number was measured on 2026-10-14 against `packages/structured-clone/src`, with throwaway scripts that are not in the repo.

1. **Adding an entry to a Map or Set, or appending to or removing from a long id list, patches one entry.** Today each is one array, and RFC 7396 replaces an array whole.
   - **The stored case is the id list.** [ADR-006](../docs/adr/006-resources-reference-by-id.md) writes `members: User[]` as a `string[]` of distinct ids, so adding one id to a 500-member list patches to 19,561 B and removing one to 19,483 B.
   - **The wire case is the org tree**, which `#buildState` rebuilds in memory with Map nodes, Set edges and `Map<Map>` permissions and sends to every client. At 1,000 nodes adding a leaf patches to 89,887 B against a 96,078 B snapshot, and one grant to 6,246 B; the same tree as plain objects patches to 111 B and 58 B. Compression does not rescue it: at 10,000 nodes, gzipped, the leaf is 104,655 B against a 111,447 B snapshot.
2. **Adding or removing a shared object changes no other object's `$ref`.** Today an alias id is a counter assigned in traversal order, so one shared object added ahead of the rest renumbers every alias after it. With 200 shared objects and one added ahead of them, the patch was 17,467 B against a 17,380 B snapshot.
3. **A `null` survives a patch.** RFC 7396 reads `null` as "delete this key", and the encoder writes a `null` as JSON `null`. So changing `{ a: 1, b: 2 }` to `{ a: 1, b: null }` produces `{"json":{"b":null}}`, the same patch as deleting `b`, and the patched value decodes without `b`. SQLite's `json_patch` follows RFC 7396 too, so a patch applied in storage would lose it the same way.
4. **A Map, Set or object-form array keeps its order through a patch.** Goal 1 replaces each array with an object, and an object patch cannot move a key. Delete `a` from `new Map([['a', 1], ['b', 2]])` and set it again, and the Map iterates `b, a`; in object form `diff` would see no change, and the patched copy would still read `a, b`. JavaScript has specified a Map's and a Set's iteration order since ES2015. A plain object's key order is the one exception this task accepts (§ *Decisions*).
5. **Every key the format can emit survives `diff` and `applyMergePatch`, `__proto__` included.** Today `diff` from `{ a: 1 }` to `JSON.parse('{"a":1,"__proto__":{"x":true}}')` returns `{"json":{}}`, and the patched value has no `__proto__` key. Decoding is already hardened against it (`test/hostile-payloads.test.ts`); patching is not. Goal 1 widens the exposure, since a Map key becomes an object key.
6. **A request's or response's body, and a sparse array's hole, round-trip.** Today `RequestSync` and `ResponseSync` copy `body` raw: a request with no body encodes `"body":null`, and an `ArrayBuffer` body decodes as `{}`. A hole encodes as `null`, so `[1, , 3]` decodes as `[1, null, 3]`, where native `structuredClone` keeps the hole.
7. **Binary encodes compactly.** Today a typed array's bytes are a JSON number array, about 3.6 characters per byte, against base64's 1.33.

## Design intent

**The encoded form is what a merge patch addresses.** Rules 1–6 shape the encoding so a one-place change in the value is a one-place change in the encoding, rules 7–9 make every patch exact, and rules 10–11 are the decoder.

1. **A Map whose keys are all strings, or all numbers, is encoded as an object**, `{"$type":"map","object":{…}}`, in the Map's insertion order. This is the object form.
   - **The escape.** A key that starts with `$`, or is an array index, gets one more `$` in front, and the decoder drops one leading `$` from any key that has one. An array index is a canonical integer string from `"0"` to `"4294967294"`, the keys JavaScript moves ahead of every other key, so `"42"` is written `"$42"` to keep its place, and a real `"$42"` is written `"$$42"`. The object form holds nothing but the Map's keys, so the rule needs no exception for the codec's own `$type`. The decoder refuses a key the encoder would never write: a key with one leading `$` whose rest neither is an array index nor starts with `$`, and an array-index key left unescaped.
   - **Number keys.** A Map whose keys are all numbers adds `"keyType":"number"`, writes each key as `String(key)` through the same escape, and decodes it with `Number`. Every number survives that, `NaN`, `Infinity` and `0.30000000000000004` included, and a Map stores a `-0` key as `0`, so `-0` cannot collide with it. The decoder refuses a number key for which `String(Number(k)) !== k`, such as `"0x10"` or `" 16"`, so two spellings cannot fold into one key.
   - **Everything else keeps `entries`**: a Map mixing strings and numbers, and one with any other kind of key. An empty Map takes the object form, with no `keyType`.
2. **A Set takes the object form the same way**: `{"$type":"set","object":{"a":1}}` with the same escape when every member is a string, adding `"keyType":"number"` when every member is a number, and `values` otherwise.
3. **An array of distinct strings whose plain form would exceed 256 bytes takes the object form**, `{"$type":"array","object":{"u1":1,"u2":1}}`, with key order as array order and rule 1's escape. Appending an element, or removing one from anywhere, patches as one entry; editing, inserting or moving one mid-array changes the key order, which rule 8 handles. Every other array stays a plain JSON array and is replaced whole by any change: a short one, since a whole-array patch under 256 bytes is already small; one holding a duplicate, a hole, a number, an object or a mix. The size is the sum of each string's `length` plus 3, held in one named constant, and the encoder checks in the cheapest order: every element a string, then the size, then distinctness, which only an array past the threshold pays for. The threshold is measured on the encode side only, so an array crossing it changes form, and that one version patches the array whole.
4. **A shared object is written in full where it first appears, and every later occurrence is `{"$ref":"#/owner"}`**, in the form of [JSON Reference](https://datatracker.ietf.org/doc/html/draft-pbryan-zyp-json-ref-03): `#` and then the JSON Pointer ([RFC 6901](https://www.rfc-editor.org/rfc/rfc6901)) of that first place in the encoding, as a plain string with RFC 6901's `~0` and `~1` escaping, hand-rolled, and no percent-encoding.
   - **The walk** is depth-first: a plain object in JavaScript's property order (integer keys first), and a Map, Set or array in insertion order. A cycle is the same case, a `$ref` to an ancestor, and a cycle through the root is `{"$ref":"#"}`.
   - **The path runs through the encoding rather than the value**, because only the encoding has a path into a Map. `{ tags: new Map([['42', s]]), pinned: s }` encodes as `{"tags":{"$type":"map","object":{"$42":{…}}},"pinned":{"$ref":"#/tags/object/$42"}}`.
   - **Each segment is the key as encoded**, escaped `$` and all, with RFC 6901's `~` written `~0` before `/` is written `~1`, so `a/b` and `a~1b` stay distinct. The empty key `''` is the segment after `#/`, distinct from the root `#`. The encoder keeps, for each object, its parent and its segment, and renders a pointer string only when it writes a `$ref`.
   - **A `$ref` changes only when its target's first appearance moves**: a new reference earlier in the walk, the first one deleted, or an element inserted ahead of it in a plain array.
   - **A pointer is rooted at the encoding it sits in**, which is what lets a stored value travel inside a message unchanged later (§ *Future state*).
5. **An encoding is the encoded value, with no wrapper.** `stringify({ title: 'Ship it' })` is `{"title":"Ship it"}`. Rule 4 leaves the wrapper nothing to hold, and an unwrapped encoding is what rule 4's pointers are rooted at.
6. **A typed array or `ArrayBuffer` carries its bytes as base64**: `{"$type":"arraybuffer","subtype":"Uint8Array","base64":"AQID"}` for `new Uint8Array([1, 2, 3])`. The bytes are the view's own window, `byteOffset` to `byteOffset + byteLength`, never its whole backing buffer, which for Node's `Buffer.from('hi')` is a 64 KB shared pool. Encoding uses the native `toBase64` and `fromBase64` where the runtime has them, and otherwise `btoa` and `atob` in chunks of about 32 KB, since one spread of a large array overflows the stack. Any malformed input throws a `DataCloneError`: a `base64` that is not a string or not base64, a length that is not a whole number of elements, or a `DataView` window outside its buffer. Binary changes as a unit, so the form makes no difference to a patch; it lands before the wipe because every app built after it carries the codec (§ *Context*).
7. **Every `null` in the value is encoded as `{"$type":"null"}`, and a sparse array's hole as `{"$type":"hole"}`, so an encoding never contains JSON `null`.** RFC 7396 reserves `null` for "delete this key", and an encoding with none in it cannot be misread by any RFC 7396 tool: ours, SQLite's `json_patch` or a library's. The decoder refuses a bare JSON `null` with a `DataCloneError`. A hole is valid only as an element of a plain array; anywhere else it is refused too.
8. **`diff` returns one of three answers: `{ kind: 'same' }`, `{ kind: 'patches', patches }` or `{ kind: 'full' }`.** A change one RFC 7396 patch can express is one patch. A collection in object form changes order when after's keys are anything but before's surviving keys, in order, followed by new ones: a reorder, or an edit or insert mid-array.
   - **Comparing two versions counts a tagged form's key order wherever it sits**, inside an array included, so a reordered Map inside a plain array changes that array and patches it whole, never `same`.
   - **Under a plain-object parent, an order change is two patches.** The first nulls the collection's key and the second sets it again, so the cost is about what replacing that collection whole costs today. The re-added key lands last in the parent, whose key order a patch does not keep.
   - **A reordered root value, or a reordered collection inside a Map or Set, is `{ kind: 'full' }`**, because re-adding it would reorder a parent whose order a patch does keep. The sender sends the full value instead.
   - **Every patch is standard RFC 7396**, applied in order: ours, SQLite's `json_patch` nested once per patch, or any library's. `diff` recognises the three tagged object forms and diffs everything else exactly as RFC 7396 does.
   - **The three answers are interfaces, `DiffSame`, `DiffPatches` and `DiffFull`, and `diff` returns their union, `Diff`.** They are interfaces, not a type alias, so none is assignable to `MergePatch` through an implicit index signature, and passing `diff`'s answer to `applyMergePatch`, which takes one `MergePatch`, does not compile.
9. **`diff` and `applyMergePatch` treat every key as data, and refuse anything that is not JSON.** Every read is an own-property read (`Object.hasOwn`, never `in` or a bare bracket read) and every write defines an own property, in `diff`, in the equality check and in the deep copy alike, so a key named `__proto__`, `constructor` or `toString` is an entry like any other: adding, changing and deleting it all patch, and none touches a prototype. An object whose prototype is neither `Object.prototype` nor `null` throws, so a decoded `Date` or `Map` handed over by mistake fails loudly instead of diffing to nothing.
10. **The decoder reads each collection's form from the value itself, and refuses any shape the encoder never writes.** It reads a Map's `object` or `entries`, a Set's `object` or `values`, and an array's object form or plain JSON array; both forms can appear in one value. It throws a `DataCloneError` on: an unknown `$type`; an unknown `keyType`; a Map or Set with both forms or neither; a member marker other than `1`; a `$ref` with sibling keys; a hole outside a plain array; a bare JSON `null`; and a non-canonical key (rule 1). An unescaped `$type` is always the codec's own, because rule 1 escapes every user key that starts with `$`, so an unknown shape means an encoding newer than this decoder or a hand-written one, and decoding it anyway, as today's `default:` branch does, would hand back the wrong value without an error.
11. **The decoder indexes the document before it decodes it.**
    - **The index holds value positions only, and only containers**: the root, a plain object's property, an array element, a value in a Map's object form or an `entries` key or value, a Set's `values` member, an Error's `cause` or own property, and a request's or response's headers or body, wherever the value there is an object, array or object-valued tag. A primitive, a `null` or hole tag, and anything else, such as `#/tags/object` (a Map's encoding) or `#/when/iso` (a Date's payload), misses the index.
    - **The index is built only when the document holds a `$ref`, keyed per container** (segment to child), never by whole pointer strings. Every container is allocated in the index pass, so a `$ref` never decodes its target on demand and the decode never recurses through a chain of forward references. The Stage 2 review measured joined pointer strings for a 1 MB document at 501 MB of index, past a Durable Object's 128 MB, and this decode runs on a browser's frame before any guard.
    - **The second pass decodes, and resolves each `$ref` by exact lookup in that index.** A patched document can put a `$ref` before its target, since a patch does not keep a plain object's order, and the lookup does not care. A pointer that misses the index (dangling, malformed, or a path like `#/__proto__` or `#/constructor/constructor` that no own key spells) throws a `DataCloneError`, and so does a `$ref` whose target is itself a `$ref`. A cycle resolves because a container exists before its children are decoded. A `$ref` from a request's or response's body to that same request or response throws too, since the constructor needs the body before the object exists.
    - **The numeric `$ref` form and the wrapper are dropped.** The wipe leaves nothing stored that uses them once test-nebula and local state are cleared, and no client older than the wipe's deploy connects, since friends-and-family invites wait for the wipe. That is also why every query hash may change in this deploy.

## Constraints

- **`.claude/rules/live.md`**: the codec's own tests run in the vitest lane, as the rule allows for a pure codec, and each new test file says why it needs no running system. Every `/live` scenario still decodes through the codec, and the codec ships in the container image, so the build also sweeps the registry and runs a deployed pass (criterion 15).
- **`.claude/rules/testing.md`**: every criterion below that changes behaviour names the mutation that reds it; the last three are the regression net, a grep, and a check by reading.

## Decisions

| Decision | Rejected alternative — why |
|---|---|
| **A Map or Set whose keys are all strings takes the object form, with one more `$` in front of any key that starts with `$` or is an array index; a Map or Set that mixes key types, or has keys that are neither strings nor numbers, keeps `entries` or `values`** (Larry, 2026-10-14) | Fall back to `entries` when any key is an array index. Changing one entry of such a Map then replaces the whole array, and string keys that are numbers, such as years or external ids, are commoner in user data than our random ids suggest. Also weighed: every Map as an object with its key order recorded in `meta`, where every reorder shows up in the patch and `meta` grows with every Map. |
| **A Map or Set whose keys are all numbers takes the object form too, marked `"keyType":"number"`** (Larry, 2026-10-14). Maps and Sets are what set the mesh apart from systems that settle for JSON, and users should be encouraged to reach for them | Leave number keys to `entries`, which a later decoder could read beside a number form. Also weighed: a per-key marker, which would cover a Map mixing strings and numbers too, at a byte on every number key and a marker character that every pointer through such a key would have to carry. |
| **An array of distinct strings whose plain form exceeds 256 bytes takes the object form; every other array stays plain** (Larry, 2026-10-14). A to-many id list then patches one id at a time with no change to the ontology, the extractor or Studio's guidance, and an edit mid-array costs about what it does today (the `diff` row below) | Encode every array by index, `{"0":…,"1":…}`. Editing one element of an array of objects would patch small, but a middle insert shifts every later index, and short numeric arrays such as coordinates and vectors grow several times over. Also weighed: teach `Set<T>` for to-many references, which needs the extractor, the write shape and the guidance changed and covers only relationships; and an element-count threshold, which treats six UUIDs like six one-letter tags. |
| **The wire vocabulary is `object`, `keyType`, the `array`, `null` and `hole` tags, `base64`, and `$ref` with a `#/…` pointer** (Larry, 2026-10-14). Each follows the existing tags' style, a lowercase noun naming what it holds, and freezes at the wipe | Rename the most generic two: `keys` for `object`, which reads as a list rather than a map, and `empty` for `hole`, which collides with an empty string or array. |
| **Every `null` is encoded as `{"$type":"null"}`** (Larry, 2026-10-14) | Tag only the positions RFC 7396 misreads, an object's property values and the top-level value, and keep plain `null` in arrays. It saves a few bytes, but the rule depends on position, the top-level case is easy to miss, and an encoding could no longer be checked for safety by searching it for `null`. |
| **A shared object is written in full where it first appears and referenced by `{"$ref":"#/…"}` after it; an encoding has no wrapper** (Larry, 2026-10-14) | Hoist every shared object into a table under its pointer, as `meta.aliases` or a top-level `aliases`. That is the smaller change to the decoder, but an object becoming shared then moves into the table and appears in the patch twice, and the wrapper the table needs puts a second `meta` in every message beside the snapshot's own. |
| **The decoder indexes the document's value positions, then decodes** (Stage 1, 2026-10-14) | Walk each `$ref`'s pointer on demand. That handles any key order too, but a naive walk over a browser's message reaches `Object.prototype` through `#/__proto__`, so it needs guards the index makes unnecessary. |
| **The transform hook is deleted; rpc swaps functions for its markers in the walk it already does** (Larry, 2026-10-14) | Keep the hook and run what it returns back through the encoder. That keeps an `@internal` hook, a recursion guard, a rule that functions are never shared, and a criterion pinning `context.path`, all for one caller whose round trip through the codec exists only to apply the hook. Also weighed: the hook must return a finished encoding, which moves encoding into rpc's markers instead of removing the need for them. |
| **`diff` returns `same`, a list of `patches`, or `full`; an order change under a plain-object parent is two patches, null then set** (Larry, 2026-10-14) | Three answers with `full` for every order change. Simpler, but a mid-array edit then sends the whole document: measured 2026-10-14, editing one step of a 12-step recipe in a value with a 1.5 KB note costs 2,353 B against 759 B today, where two patches cost 824 B. Also weighed: give only the arrays a caller marks as references the object form, which the codec cannot do without a marker in the value, since it never sees the ontology. |
| **The answers are named `DiffSame`, `DiffPatches` and `DiffFull`, and their union `Diff`** (Larry, 2026-10-14). Each is `Diff` plus the `kind` value it carries | `Unchanged`, `Patches` and `FullValue` in a union called `DiffResult`. Each reads well alone, but drifts from the `kind` values, so a reader switching on `kind` maps between two vocabularies. |
| **A patch keeps every Map's, Set's and object-form array's order, and a plain object's properties and values but not their order** (Larry, 2026-10-14) | Keep every order, plain objects included. A resource's value is a plain object at its root, so every form that rebuilds a value in schema order would send the full value, to keep an order in which JavaScript puts integer keys first anyway. Also weighed: keep no order at all, which lets a patched Map iterate differently from a fresh read of the same eTag, against the order ES2015 gives Maps and Sets on purpose. |
| **Two readers of one version may see a plain object's keys in different orders, and ADR-002 says so** (Larry, 2026-10-14). A fresh read of `{ title, dueDate, status }` keeps that order; a copy patched from `{ title, status }` reads `title, status, dueDate`. It shows only where code iterates the keys of a dictionary rebuilt in a new order, and an order that matters belongs in a Map or an array | Write each version in its predecessor's key order in `#writeSnapshot`, appending new keys, so every reader agrees. It costs a walk per write, ignores a writer who sorts a dictionary's keys, still diverges across a catch-up spanning a delete and re-add, and moves Resources work into a codec task. |
| **The org tree's creation order is deferred to [nebula-pre-alpha-fast-follow.md](nebula-pre-alpha-fast-follow.md) § *Item 14*, as something to consider** (Larry, 2026-10-14) | Add a ULID order column to `Nodes`, `Edges` and `Permissions` here. The org tree is rebuilt in memory and sent, never stored in this encoding, so the wipe does not bind it, and a column added later fills existing rows in primary-key order. Ordering `Permissions` by its own column also leaves the outer `permissions` Map following each node's earliest surviving grant, so one revoke can resend the whole tree; fixing that reshapes state Item 14 will design. |
| **Typed arrays and `ArrayBuffer`s carry their bytes as base64** (Larry, 2026-10-14) | Keep the number array and switch later. A stored row could be decoded in both forms, but every app built before the switch could not decode the new one until rebuilt, unless the server sent each app the form its build knows. Typed arrays are rare in Larry's designs, but today the change is one tag. |
| **This task changes the stored form and `diff`; sending patches is fast-follow** (Larry, 2026-10-14). Rules 1–7, 10 and 11 are what the wipe binds. Rules 8–9 change only `diff` and `applyMergePatch`, which nothing outside the package calls yet, and ride here because the size criteria run through `diff` | Build merge-patch sync before pre-alpha too. Only the stored form is wipe-bound. |

## Success criteria

Pass 2 assigns each to a phase. Sizes are raw `JSON.stringify` bytes, so no test needs `zlib`.

1. **A Map entry patches small.** On the org tree's shape at 1,000 nodes, with Map nodes, a Set of edges and `Map<Map>` permissions, each built in creation order, adding a leaf patches to at most 300 B, and one grant to at most 150 B. *Mutation:* encode every Map as `entries`.
2. **A Set member patches small.** Adding one `parentId:childId` edge, two 36-character ids joined by `:`, to a Set of 1,000 such edges patches to at most 120 B (measured about 100 B; the `values` form patches about 76 KB). *Mutation:* encode every Set as `values`.
3. **An array-index key keeps its place.** `new Map([['b', 1], ['42', 2]])` encodes as `{"$type":"map","object":{"b":1,"$42":2}}` and decodes with `b` first, a real key `'$42'` round-trips as itself beside `'42'`, and `new Set(['b', '42'])` does the same. *Mutation:* drop the `$` for an array-index key, so `'42'` decodes first; or skip it for a key that starts with `$`, so `'$42'` and `'42'` collide.
4. **A number-keyed Map patches small and keeps its keys.** `new Map([[2026, 'a'], [1.5, 'b'], [NaN, 'c'], [-1, 'd']])` decodes with number keys in that order, and adding one entry to a 1,000-entry `Map<number, string>` patches to at most 100 B. `new Map([['a', 1], [2, 2]])`, mixing types, keeps `entries`. *Mutation:* drop `keyType`, so the keys come back as strings; or skip the escape for a number key, so `2026` moves ahead of `1.5`.
5. **A 500-id list patches small, and the arrays that should stay plain do.** Appending one id to a 500-id array of distinct strings patches to at most 100 B, and so does removing the fourth. An array of 8 UUIDs that repeats one (313 B), `['red', 'green', 'blue']`, and an array of long distinct strings over 256 B with a hole all encode as plain JSON arrays, the last keeping its hole and its length. A distinct array over 256 B encodes as exactly `{"$type":"array","object":{…}}`, and an array growing past 256 bytes decodes the same in both forms. *Mutation:* drop the distinctness check, so the 8-UUID array takes the object form and loses its repeat; drop the threshold, so the three tags take the object form; skip holes in the element check, so the sparse array loses its hole; or encode every array plain.
6. **A shared object keeps its pointer, through every kind of segment.** A `rows` object holds 200 objects of the shape `{ id: '<uuid>', label: 'Row n' }`, each under two keys; adding one more shared pair under a `pinned` object that the encoder walks before `rows` patches to at most 500 B. A shared object first seen under each of these round-trips as one object (`toBe`): a Map key `'42'` in object form, a plain key `'$$x'`, the keys `a/b` and `a~1b` holding different objects, the empty key `''` beside a cycle through the root, and an own `__proto__` key. A document whose keys a patch has reordered, so a `$ref` comes before its target, decodes to the same shared object. Cycles, shared identity and `test/aliases.test.ts` still pass. *Mutation:* number the `$ref`s by a counter again; build a segment from the raw key rather than the encoded one; skip `~` escaping, or escape `/` before `~`; refuse every `__proto__` segment; or resolve a `$ref` only from targets already decoded.
7. **A hostile or misplaced pointer is refused, and a hostile document is bounded.** Each of these throws a `DataCloneError` from `parse`, and `Object.prototype` gains nothing (`test/hostile-payloads.test.ts`): a `$ref` of `#/__proto__` or `#/constructor/constructor` in a document with no such own key; a dangling pointer; `#/m/entries/0` (a Map's `entries` pair, not a value); `#/tags/object` (a Map's encoding); `#/when/iso` (a Date's payload); a `$ref` to a `$ref`; and a body's `$ref` to its own request. Every existing row that went through the old `{"$ref":0}` path is rewritten through a forward pointer, such as `[{"$ref":"#/1"},{"__proto__":{"isAdmin":true}}]` and `[{"$ref":"#/1"},{"$type":"error","name":"Tripwire","message":"m"}]`. Each of these decodes, or is refused, with heap growth under 32 MB: 1,000 levels of 1,000-character keys; 4,000 same-length siblings under a key longer than 16 KB; and 20,000 forward references. *Mutation:* index by joined pointer strings; decode a `$ref`'s target on demand; on an index miss, fall back to walking the parsed document; or assign `__proto__` when allocating a `$ref`'s target.
8. **An encoding has no wrapper.** `stringify({ title: 'Ship it' })` is exactly `{"title":"Ship it"}`. *Mutation:* emit the `{ json, meta }` wrapper.
9. **A `null` survives a patch, a hole survives at all, and every form round-trips together.** Changing `{ a: 1, b: 2 }` to `{ a: 1, b: null }` and applying the patch decodes with `b` an own key holding `null`, and a top-level `null` does the same. `[1, , 3]` decodes with its hole. A corpus nesting an object-form Map that holds a number-keyed Set, an object-form array over 256 B referenced twice, an `entries`-form Map with object keys, a `null`, a holed array and a typed array round-trips deep-equal, with `toBe` on every shared reference, and encodes with no JSON `null` anywhere. A bare JSON `null`, and a hole outside a plain array, each throw a `DataCloneError`, directly and through a forward `$ref`. *Mutation:* emit a property's `null` as JSON `null`; encode a hole as one; or decode a hole outside an array.
10. **Binary travels as base64, exactly the view's bytes.** A `Uint8Array` of 1,000 random bytes encodes its bytes in at most 1,400 characters and decodes byte for byte; a 1 MB array round-trips; `Buffer.from('hi')` encodes two bytes, in the node project; `subarray(10, 20)`, a `Float64Array` at `byteOffset` 8 and a `DataView` window each round-trip their own window; an `ArrayBuffer` round-trips. A `base64` that is not a string, not base64, or not a whole number of elements, and a `DataView` window outside its buffer, each throw a `DataCloneError`; these replace hostile-payloads' rows for `data` given as a length. *Mutation:* encode `data` as a number array again; encode with one spread, so the 1 MB array overflows; encode `.buffer`, so `Buffer.from('hi')` sends its pool; or drop the string check.
11. **A shape the encoder never writes is refused.** Each throws a `DataCloneError`, directly and through a forward `$ref` such as `[{"$ref":"#/1"},{"$type":"not-a-tag"}]`: `{"$type":"not-a-tag","x":1}`; `{"$type":"map","keyType":"bigint","object":{"1":"a"}}`; a Set with an unknown `keyType`; a Map with both `object` and `entries`, or neither; a Set member marker of `2`; a `$ref` with a sibling key; an object-form key `"$x"`; an unescaped object-form key `"42"`; and a number key `"0x10"`. A user object with its own `$type` key still round-trips, escaped as `$$type`. *Mutation:* restore the `default:` branch; read an unknown `keyType` as strings; or decode keys with `Number` without the canonical check.
12. **A request's or response's body is encoded like any value.** A `RequestSync` with no body and `ResponseSync(null)` encode no JSON `null`, a `ResponseSync` with an `ArrayBuffer` body decodes with its bytes, and `packages/mesh/test/client-gateway.test.ts`'s answer that will not decode asserts the new `DataCloneError` message exactly. *Mutation:* copy `body` raw again.
13. **An order change costs about what replacing the collection costs today, and is never lost.** Every case below applies its patches in order and decodes deep-equal, with key order checked.
    - **The cost.** Editing step 6 of 12 steps of about 60 characters each, held at a top-level key in object form, returns two patches totalling at most 1.2 times `JSON.stringify(steps)` (measured about 1.10).
    - **Two patches or `full`.** Deleting a plain-object field's Map key and setting it again returns two patches; the same reorder in a Map that is the root value, or inside another Map, returns `{ kind: 'full' }`. A plain object rebuilt as `{ title, dueDate, status }` from `{ title, status }` returns one patch, `{"dueDate":…}`, and decodes with all three properties.
    - **Compound changes:** a reordered Map beside a changed sibling; two reordered Maps under different parents; and a reordered Map inside a plain array, which patches the array whole and never answers `same`.
    - **Form switches:** a Map gaining a number key, so it switches to `entries`; a Set gaining a non-string member; an array crossing 256 bytes in each direction, and gaining a duplicate; and a shared object whose pointer moves with such a switch, keeping its identity.
    - **Catch-up.** `{a, b}` through `{b}` to `{b, a}` decodes to `b, a` both step by step and by one `diff` from first to last.
    - **SQLite parity.** In the node project, every patch list above, applied through nested `json_patch` in `node:sqlite`, decodes to the same value as `applyMergePatch`.
    - **Types.** A `// @ts-expect-error` line passing `diff`'s answer to `applyMergePatch` holds under `npx tsc --noEmit -p packages/structured-clone`.
    - *Mutation:* answer a mid-array edit with one patch, so the steps come back `a, c, b2`; return early after the first order change; keep an order-blind equality inside arrays; read `Object.keys(after.object)` without checking which form `after` has; or declare the answers as a type alias, so the `@ts-expect-error` line fails.
14. **Every key is data to `diff` and `applyMergePatch`, and `diff` refuses a decoded value.** Each of these patches and applies correctly, and `Object.prototype` gains nothing: adding, changing and deleting a plain key `constructor`, a Map entry named `toString`, a Set member named `valueOf`, and an own `__proto__` on a plain object and in `new Map([['__proto__', 1]])`; adding a nested object under `toString`; and an own `__proto__` inside an array element and inside a newly added subtree, whose decoded objects keep `Object.prototype` and inherit no `isAdmin`. `diff(new Date(0), new Date(1))` throws, under its own `// @ts-expect-error`, and the encode, diff, apply and decode round trip type-checks with no `as`. *Mutation:* each site separately: `in` in `diff`; `in` in the equality check; a bracket read in `diff` or in apply; plain assignment in `diff`, in the deep copy, or in apply; or drop the prototype check, so the two Dates diff to nothing.
15. **Nothing else changed, locally or deployed.** In order: `npx tsc --noEmit -p packages/structured-clone` and `npm run test:code` pass, the RFC 7396 Appendix A suite included, covering every package that encodes with structured-clone; a local `drive.ts all`, container scenarios included, passes; then test-nebula is cleared and redeployed (Phase 4) and the deployed pass passes, ending with test-nebula's Workers Issues read since the pass began. Not run at review time: it is the build's own net, and its type-check step already passes against today's tree. *Mutation:* none; this is the regression net under the rest.
16. **No description of the old format survives.** `grep -rnE 'meta\.aliases|\{ ?json, ?meta|meta: \{\}|LmzIntermediate|sidecar|\bW4\b|\["\$lmz"|tuple-(based|style)'` over `website/docs` (excluding the generated `api/` pages), `packages/structured-clone/src`, `packages/structured-clone/test` and `packages/mesh/test` finds only `website/docs/mesh/protocol.mdx`'s comparison with Cap'n Web, which describes Cap'n Web's format; and `npm run test:doc` passes. Run against today's tree on 2026-10-14, it finds 56 lines, so it can fail. *Mutation:* none; the grep is the instrument.
17. **ADR-002 states its one exception and describes the format that ships.** [ADR-002](../docs/adr/002-structured-clone-everywhere.md) says a patch keeps a plain object's properties and values but not their key order, so a patched copy and a fresh read of one version may order its keys differently, and an order that matters belongs in a Map or an array. Its Decision and Consequences paragraphs no longer present the W4 format as current; the Evidence line, which is history, stays. ADR-002's line in `.claude/rules/workflow.md` § *Architecture commitments (ADRs)* names the exception too, since that line loads every session. *Mutation:* none; it is checked by reading.

## Build notes

### Before Phase 1 (2026-10-14)

- **Baseline:** `npm test` in `packages/structured-clone` passes 49 files and 1,066 tests. Its `placeholder.test.ts` "Could not resolve" warnings are older than this build.
- **`PathElement` has a second user.** Besides the transform hook, `formatPath` in `preprocess.ts` renders the value path into the `DataCloneError` message for an unencodable object ("at session.keys[0]"). Deleting the hook removes the exported `PathElement`, `PreprocessContext`, `PreprocessTransform`, `PreprocessOptions` and `TRANSFORM_SKIP`, but the encoder keeps an internal value path for that message, beside the new encoding-pointer segments.
- **`stringify` takes `options?: PreprocessOptions`** (`index.ts`), so its signature loses that parameter when the hook goes.
- **Typed arrays encode element by element today**, each through `encodeBody`, so a `Float64Array`'s `NaN` and a `BigInt64Array`'s bigints carry tags. Base64 over the bytes (rule 6) carries them exactly, with no per-element tags.
- **The decoder's `function` case copies any extra keys** besides `name` (in `decodeValue` and `fillContainer`), though `preprocess` emits only `name`. Rule 10's "refuses what the encoder never writes" applies to it too.
- **`decodeRequestSync` and `decodeResponseSync` construct with `data.body`** (`web-api-encoding.ts`), so the body has to be decoded before the object exists. That is why rule 11 refuses a body's `$ref` to its own request or response.
- **`merge-patch.ts`'s own-property gaps are where Stage 2 placed them:** `!(key in after)` in `diff`, `before[key]` and `after[key]` bracket reads, `k in b` in `jsonEqual`, and `out[k] =` in `deepClone`.

### Phase 1 (2026-10-14)

**What landed.** `preprocess` walks once and writes `{"$ref":"#/…"}` pointers through the encoding; `postprocess` indexes value positions per container, only when the document holds a `$ref`, then fills; the wrapper, `LmzIntermediate` and the transform hook are gone; rpc builds its own markers in `copyResultForWire` (`packages/rpc/src/lumenize-rpc-do.ts`, the walk that was `flattenPrototypeChains`), and `packages/rpc/src/rpc-transforms.ts` is deleted.

**Gate:** `npm run test:code` passes. `packages/structured-clone` went from 49 files and 1,066 tests to 52 and 1,156, `packages/rpc` from 22 and 333 to 23 and 335, and `packages/testing` from 205 tests to 206; `npx tsc --noEmit` passes for structured-clone, rpc, testing, mesh, resources, `apps/nebula` and its harness.

**For the human:**

- **rpc's copy keeps a result as it was when its call returned.** The round trip did that silently: in one batch, `getLiveState()` then `bumpLiveState()` answered `{ n: 0 }` for the first call, because the result was decoded fresh before the second call ran. The task file did not name this. `copyResultForWire` copies every plain object, array, Map and Set to keep it, and `test/function-markers.test.ts` pins it.
- **One small difference from before:** a function in an Error's own property, on an Error a method *returns*, now arrives as the codec's `{ name }` marker rather than a remote function marker, since the walk does not copy Errors. A thrown Error never went through this path. rpc exists only for testing, so I left it; say if you want Errors copied too.
- **Rule 10's refusal of a `$ref` with sibling keys landed here**, with its `test/hostile-payloads.test.ts` row, because this phase rewrote the `$ref` decode. Phase 2 adds the rest of rule 10.

**Retro:**

- **Removing the round trip fixed a real bug.** The hook put its marker into the encoding unencoded, so the decode that followed treated the marker's arguments as wire data: an argument key `$$x` came back `$x`, and a `Date` argument came back `{}`. `packages/testing`'s new replay test reds on the old code for exactly that.
- **Restoring the round trip without the hook does not red**, because a marker is now encoded as data and the codec round-trips it exactly. The round trip was redundant, not wrong.
- **`RequestSync` copies the `Headers` it is given**, when it is built and again when it is decoded, so a `Headers` shared with a request keeps its pointer, `#/request/data/headers`, but not its identity. That was true before too.
- **The heap bound needed the right emulation to fail.** V8 keeps `parent + '/' + key` as a rope, so an index keyed by concatenated pointers stays small; only a pointer rendered whole from its segments, `'#/' + segments.join('/')`, reproduces the Stage 2 figure. Under that mutation the 1,000-level document fails at 501,754,704 bytes. The correct decode of the 20,000 forward references grows Node's heap by about 12 MB, within the 32 MB bound.
- **Mutations:** caught were the wrapper; a segment from the raw key; no `~` escape, and `/` escaped before `~`; refusing every `__proto__` segment; resolving only to containers met earlier in document order, which reds exactly the two reordered-document tests; walking the parsed document on an index miss; filling a target when its `$ref` resolves (stack overflow on the forward chain); the joined-pointer index; plain assignment of `__proto__`; and in rpc, skipping Map values, seeding `seen` with the original, and sharing unchanged originals.

**Close-out:**

- `website/docs/structured-clone/index.mdx`'s Tier 2 line now reads `// Returns plain JSON`, with its `@check-example` source in `test/for-docs/api-tiers.test.ts`; the rest of that page is Phase 4's.
- `preprocess.ts`'s header paragraph on aliases is rewritten for pointers; the rest of each header is Phase 4's.
- `defaultEncodeBody` and `defaultDeencodeBody` in `web-api-encoding.ts` had no caller before this build; Phase 2's body work deletes them.
- `packages/rpc/test/lumenize-rpc-do.test.ts`'s header names `#preprocessResult`, which no longer exists; it predates this build.

### Phase 2 (2026-10-14)

**What landed.** A Map or Set whose keys are all strings or all numbers takes the object form, `keyType: "number"` marking the second; an array of distinct strings over `ARRAY_OBJECT_FORM_MIN_BYTES` (256) takes it too; `null` and a hole are tags; binary is base64 of the view's own window (`src/base64.ts`); a request's or response's `headers` and `body` both go through one field callback; and the decoder refuses every shape rule 10 lists, a function tag carrying more than its name included. `packages/mesh/test/client-gateway.test.ts`'s undecodable answer is rebuilt on a `base64` that is not base64.

**Gate:** `npm run test:code` passes. `packages/structured-clone` is at 55 files and 1,315 tests, 2 of them skipped: the Node-only `Buffer.from('hi')` case in the workers and chromium projects.

**For the human:**

- **A DataView travels as its own bytes, with no `byteOffset` or `byteLength`,** as I said at the Phase 1 hand-off, and the decoder refuses an `arraybuffer` naming either. That refusal is what "a `DataView` window outside its buffer" in criterion 10 now tests.
- **A `subtype` that names no typed array still decodes as a `Uint8Array` of its bytes.** Rule 10 does not list `subtype`, and `test/hostile-payloads.test.ts` already pins that fallback for `Map`, `WebSocket` and the rest, so I kept it.

**Retro:**

- **The criterion's "skip holes in the element check" mutation exposed a line that could not matter.** A hole reads as `undefined`, which the string check already refuses, so my `Object.hasOwn(value, i)` beside it decided nothing. It is gone; the mutation that reds is iterating with `every`, which skips holes, and the comment on `isLongDistinctStringList` now says so.
- **Bytes now travel in the platform's byte order**, as native `structuredClone` copies them, where the old number arrays were order-free. Workers, browsers and Node on x86 and ARM are all little-endian.
- **Base64 is checked against one pattern before any decoder sees it**, so `atob` in Node and `Uint8Array.fromBase64` where a runtime has it refuse the same strings.
- **Mutations:** all 21 named for criteria 3, 4, 5, 9, 10, 11 and 12 were caught, each by the test meant to catch it, and so were 12 more on refusal rows the criteria name no mutation for: both or neither form, the member marker, a needless escape, an unescaped index, a function's extra keys, entries that are not pairs, `keyType` beside entries, a body's `$ref` to its own request, a `$ref` to a Map's `object`, a JSON `null`, an `arraybuffer` window, and a byte count that is not whole elements.

**Close-out:**

- Phase 1's close-out item is done: `defaultEncodeBody` and `defaultDeencodeBody` are deleted from `web-api-encoding.ts`.
