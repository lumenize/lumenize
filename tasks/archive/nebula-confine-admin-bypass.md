# Confine the `access.admin` bypass to the DO it actually covers

**Status:** ✅ **DONE 2026-07-21 — all four phases built, verified, and committed** (`84d3510` guards + lane, `e75731b` annotations, `b16d845` verifier fixes). 405 passed / 1 skipped in `apps/nebula` (baseline + dev-studio + unit), 196/197 in `packages/nebula-auth`, type-check clean. **The hole described below is CLOSED** — the past-tense sections are kept because the reasoning is load-bearing for the tasks this one gates, not because anything is outstanding.

⚠️ **Releases both dependents:** [nebula-auth-identity-mint.md](../nebula-auth-identity-mint.md) Phase 1 and [nebula-galaxy-collapse-and-chat.md](../nebula-galaxy-collapse-and-chat.md). Neither is gated any more.

*History:* surfaced 2026-07-19 by the `/review-task` framing panel on identity-mint (finding B1). Reachability was re-derived twice by this file's own framing panels — two revisions got it wrong in opposite directions before landing on `/delegated-token` narrowing as the real vector (see *How this was reachable*). The generalized invariant is now **ADR-015** (scope authority flows strictly downward).

**Objective:** an `access.admin` caller must be treated as admin **only on nodes its `authScopePattern` actually covers.** Two guards — and one *stored copy* of the admin bit — trust the bare `admin` flag with no reference to *which DO they are running in*, so an admin of a child scope acts as admin on its ancestors.

## The bug (fixed — past tense throughout)
Admission and authority are decided by two different checks, and only the first considers the DO's identity.

**Step 1 — admission.** `enforceScopeReach` ([nebula-do.ts:66-101](../../apps/nebula/src/nebula-do.ts)) accepts a call iff **either** the caller is an `access.admin` whose pattern covers this DO's name (`:89`), **or** the caller's `aud` falls under this DO's scope (`:98`, the tenant branch). A Galaxy-scoped caller reaching the **Universe** DO:
- `:89` — `matchAccess('{u}.{g}.*', '{u}')` → **false** (falls through)
- `:98` — `pattern = buildAuthScopePattern('{u}')` = `'{u}.*'`; `matchAccess('{u}.*', aud='{u}.{g}')` → **TRUE → admitted**

Admission via the tenant branch is arguably intended (a member of a child may read its parent). **The bug is what happens next.**

**Step 2 — authority.** The admin checks then key on the bare bit, with no idea which node they are in. Three bare-bit readers, at **two** confinement points:

### (A) `requireAdmin` — the whole `@mesh(requireAdmin)` surface
[nebula-do.ts:33-38](../../apps/nebula/src/nebula-do.ts) — `if (!claims?.access?.admin) throw`, and nothing else. Every `@mesh(requireAdmin)` method on an **ancestor** node is reachable by a descendant-scope admin admitted through the tenant branch. Take the inventory by grep rather than trusting a snapshot — it changes with the collapse:

```sh
grep -rn '@mesh(requireAdmin)' apps/nebula/src
```

Worst current targets: `Universe.setUniverseConfig` + the inherited [`teardown()`](../../apps/nebula/src/nebula-do.ts) (`:136`, `ctx.storage.deleteAll()`) from a galaxy-scoped principal; the Galaxy set from a star-scoped one. ⚠️ **The collapse multiplies this set** — `DevStudio`'s and `DevContainer`'s ~19 `@mesh(requireAdmin)` methods (including `chat()`, which spends the owner's AI budget and triggers a container build) fold onto `{u}.{g}`.

### (B) The DAG permission plane — `requirePermission`, `evaluatePermissions`, and the stored bit
- [dag-tree.ts:159](../../apps/nebula/src/dag-tree.ts) `requirePermission` — `if (claims?.access?.admin) return sub`, short-circuiting **before** any DAG lookup. Reads the **live** claim. **Confinement point 1.**
- [subscriptions.ts:165](../../apps/nebula/src/subscriptions.ts) + [query-subscriptions.ts:126](../../apps/nebula/src/query-subscriptions.ts) — persist `claims.access.admin` as a raw 0/1 column at **subscribe** time. **Confinement point 2** (the push path never re-reads the JWT, so confining only the live claim leaves this back door open).
- [dag-tree.ts:442-451](../../apps/nebula/src/dag-tree.ts) `evaluatePermissions` — `if (accessAdmin || resolvePermission(…))`, the non-throwing push-time twin, consumed at [resource-data-plane.ts:157](../../apps/nebula/src/resource-data-plane.ts) / `:458` / `:538`. **Not** a third confinement point — it takes no instance name, so confining the store is what fixes its **push**-path operand. ⚠️ It has a *second* operand source: it is also mesh-reachable with a caller-supplied `accessAdmin` (via the bare `@mesh()` `dagTree()` accessor). That path is harmless for a separate reason — see Phase 2 — and the two reasons must not be conflated.

### Arming model — principal × surface
Both halves need the same two things: a **principal** whose pattern sits below the DO, and a **surface** it can reach. Neither half "belongs" to one task:

| | Today | + identity-mint Phase 1 | + the Galaxy collapse |
|---|---|---|---|
| **Principal** | `/delegated-token` only (caller already holds ancestor authority) | **any invited admin, at any tier** — the general case | unchanged |
| **§A surface** | Universe + Galaxy `@mesh(requireAdmin)` | unchanged | **~19 more methods** fold onto `{u}.{g}` |
| **§B surface** | none (every DagTree host is a star-tier leaf) | unchanged | **first DagTree on a non-leaf** (Galaxy `{u}.{g}`) |

So: **both halves arm on the first freely-mintable sub-universe admin** (identity-mint Phase 1); the collapse independently widens §A's target set **and** creates §B's surface. §B genuinely needs *both* — a non-leaf DagTree host and an admin principal below it.

The collapse's escalation reads: `buildAuthScopePattern('{u}.{g}')` = `{u}.{g}.*` ([parse-id.ts:118](../../packages/nebula-auth/src/parse-id.ts)) → the tenant branch admits a caller with `aud={u}.{g}.dev`; their star-tier pattern is the *exact id* (`:117`) so the reach branch never fires — admitted purely as a tenant, then `dag-tree.ts:159` hands them admin over the whole Galaxy chat DAG (`ROOT_NODE_ID`, `SESSION_NODE_ID`, cascading write).

### How this WAS reachable (pre-fix)
⚠️ **`authScopePattern` is not minted by `#mintIdentity`.** Two earlier revisions of this file enumerated the three `#mintIdentity` call sites, found only universe-tier (`{u}.*`) and platform (`*`) admins, and concluded "unreachable." That is the wrong enumeration: the pattern comes from `mintAccessToken`'s **explicit override**, and exactly one caller sets it independently — `handleDelegatedToken` ([worker-token.ts:345-351](../../packages/nebula-auth/src/worker-token.ts)).

`/delegated-token` ([router.ts:49](../../packages/nebula-auth/src/router.ts), reachable from `apps/nebula` via `entrypoint.ts:110`) is gated only by an **upper** bound — `matchAccess(caller.authScopePattern, activeScope)` at `:324` — which permits arbitrary **narrowing**. A `{u}.*` admin requesting `activeScope={u}.{g}` gets back `aud={u}.{g}`, `authScopePattern={u}.{g}.*`, `admin: true`: exactly the §A principal. This is shipped, tested behavior — [nebula-auth-delegation.test.ts](../../packages/nebula-auth/test/nebula-auth-delegation.test.ts) *"binds the minted token to the REQUESTED scope, not the caller pattern"* asserts precisely that token shape.

**Why it is bounded:** the caller must already hold authority over the ancestor, so they gain no reach they lacked. What breaks is the endpoint's own guarantee — a token deliberately scoped down to `{u}.{g}`, minted to act as *another subject*, still wields Universe-admin authority. Scope-reduction is not reduction. (`security.md`'s delegation rule (2) exists because the absence of its sibling invariant was a real escalation; this is the same family.)

**Consequence for testing:** the principal under test is producible **today, through a production path** — no ADR-009 rung agonizing, no dependence on the dead `createSubject.isAdmin` option, no circular wait on identity-mint.

### Why the existing comments believed it was safe
- `dag-tree.ts:159` — *"`access.admin` is only minted with an `aud` inside the admin's authScopePattern … so trusting it here is sound: the Star is provably within the admin's scope."* That establishes **aud ⊆ admin's pattern**. It does **not** establish **this DO ⊆ admin's pattern**. The conclusion holds today only because **every DagTree host is a star-tier leaf** ([star.ts:52](../../apps/nebula/src/star.ts), [dev-studio.ts:153](../../apps/nebula/src/dev-studio.ts)) — a property the comment never states and nothing enforces, and which the Galaxy collapse deletes.
- `requireAdmin`'s JSDoc — *"A galaxy-A admin is still rejected by onBeforeCall from reaching galaxy B."* True for **siblings**; the reasoning never considers the **ancestor** direction.

**The lesson this task encodes:** a guard justified by an incidental property, rather than an enforced invariant, is a guard that silently expires. Every annotation this task writes must name an invariant — and every test it writes must be capable of failing.

## The fix
Confine each admin check to the node it is running in: treat `access.admin` as authority **only when `matchAccess(authScopePattern, <this node's instance name>)`**. Where that fails, fall through to the ordinary path — `resolvePermission`'s DAG lookup for the permission sites, and a throw for `requireAdmin`.

- **Cost: zero I/O.** Both inputs are already in hand — `authScopePattern` from the verified JWT on `callContext.originAuth`, and the node's own framework-stamped instance name — and `matchAccess` is a pure string function. **No Registry read, no KV read.** The hot login/refresh path is untouched, and the ~99% non-admin caller never enters the admin branch. In the deny case it is *cheaper* (rejects before the DAG lookup).
- **One predicate, four hand-rolled copies to collapse** (ADR-007, "one guard path, one place to audit"). ⚠️ **The exported body is NOT any of the four verbatim — it takes the strongest form:**

  ```ts
  export function hasAdminOverScope(access: AccessEntry | undefined, scope: string): boolean {
    if (!access?.admin || !access.authScopePattern) return false;   // ← the guard only nebula-do.ts:89 has
    return matchAccess(access.authScopePattern, scope);
  }
  ```

  | Site | Today | After |
  |---|---|---|
  | [nebula-auth-registry.ts:867](../../packages/nebula-auth/src/nebula-auth-registry.ts) `#hasAdminOverScope` | `admin` check only, **no pattern guard** | delegates — **strengthened** |
  | [:882](../../packages/nebula-auth/src/nebula-auth-registry.ts) `#hasAdminOverGalaxy` | byte-identical to `:867` | delegates — **strengthened** |
  | [:873](../../packages/nebula-auth/src/nebula-auth-registry.ts) `#hasAdminOverUniverse` | hand-rolled 3-branch | delegates (provably equivalent — see Decisions) |
  | [nebula-do.ts:89](../../apps/nebula/src/nebula-do.ts) `enforceScopeReach` reach branch | `admin && authScopePattern && matchAccess(...)` | delegates — **behavior-preserving** (it already has the guard) |

  Without the guard the collapse would *delete* a defensive check: `matchAccess(undefined, x)` throws `TypeError` at [parse-id.ts:142](../../packages/nebula-auth/src/parse-id.ts) (`.endsWith` on `undefined`) rather than returning `false`, converting a clean branch denial into an opaque error at four sites and undercutting the distinct-message criterion below. **Exploit delta is nil** (a throw is a DENY everywhere, and a verified token always carries the required `authScopePattern` — `types.ts:44`), so this is spec precision, not a live hole. Add a unit assertion that a pattern-less admin claim returns `false`.
- **Plumbing — three component signatures change, not one.** Host → `ResourceDataPlane` (**2 construction sites**: [star.ts:52](../../apps/nebula/src/star.ts), [dev-studio.ts:153](../../apps/nebula/src/dev-studio.ts)) → `DagTree` / `Subscriptions` / `QuerySubs` (one new param each — all three need it: `DagTree` to confine `requirePermission`, the other two to write the confined verdict). `CallContext` carries no self instance name, so the host must supply it. **Pass a thunk, never a captured value** — mirror `#getCallContext` ([dag-tree.ts:34](../../apps/nebula/src/dag-tree.ts), fed by `() => this.lmz.callContext` at `star.ts:53`): `ResourceDataPlane` is built in `onStart()`, where `this.lmz.instanceName` is not yet stamped, and `Star.resetDevData` re-runs `onStart()` after a `deleteAll()` that wipes the identity key. A new **required** ctor param reds both hosts at type-check, so no host can silently slip.
  `requireAdmin` does **not** reach the name today: `HasCallContext` ([nebula-do.ts:19](../../apps/nebula/src/nebula-do.ts)) is a **module-private structural alias** (three references, all local — *not* exported; `index.ts:6` exports the functions, not the type), so widening it is free. Add `instanceName?: string`.
  ⚠️ **Optional, not required.** `LmzApi.instanceName` is `readonly instanceName?: string` ([lmz-api.ts:478](../../packages/mesh/src/lmz-api.ts)); a required `instanceName: string | undefined` fails to compile for `NebulaDO` itself (TS2345). (Verified safe: `MeshGuard<T = any>` infers `T` from the guard, so no `@mesh(requireAdmin)` site breaks.)
- **Absent instance name → throw (fail closed).** Permanently `undefined` on a `LumenizeWorker`. **Never coerce** (`?? ''` denies every scoped admin; `!` opens the hole).
  ⚠️ **Mirror only branch (a) — and name why the others don't travel.** `enforceScopeReach`'s branch ORDER is load-bearing (`nebula-do.ts:57-61`): the platform-name reject (b) and the `buildAuthScopePattern` parse (d) run *before* the reach clause, because `matchAccess('*', x)` is true for any string including an unparseable name. The confined `requireAdmin` calls the predicate on a raw name with no such ordering. **The invariant that makes that sound:** `onBeforeCall` always precedes guard execution ([lmz-api.ts:964](../../packages/mesh/src/lmz-api.ts) → [ocan/execute.ts:120](../../packages/mesh/src/ocan/execute.ts)), and both `NebulaDO:153` and `NebulaContainer:49` compose `enforceScopeReach` — so (b)/(d) have already run on every node that composes both. Branch (a) still needs mirroring anyway: a name-less `LumenizeWorker` could compose `requireAdmin` *without* `enforceScopeReach`. State this rather than adding redundant checks — but state it, because "already caught upstream" is the incidental-property reasoning this task exists to eliminate.
- **The confined denial gets its own message.** "You are an admin, but not of *this* node" is a different user action from "you are not an admin". ADR-008 disclaims confidentiality of the scope boundary and discloses the denied set on purpose, so there is no disclosure objection, and both operands are already in the caller's own JWT. Name the node and the caller's covered scope (e.g. `Admin access required for {u} — your admin scope is {u}.{g}.*`). Precedent: `PermissionDeniedError` carries `nodeId`; `enforceScopeReach` has three distinct branch messages.

### Legitimate callers — the class, the invariant, and the silent-failure hazard
⚠️ **Nearly every cross-node call into a `@mesh(requireAdmin)` method is 3-arg fire-and-forget, so a denial is *silent*** — no result channel exists, the work simply stops. That makes an over-tight predicate far more dangerous than an over-loose one during the build. **Regenerate the inventory mechanically before building** (`grep -n 'lmz\.call(' apps/nebula/src apps/nebula-studio-ui/src`) — the collapse reshapes it. As of 2026-07-20, separating **call sites** from **callees**:

| Call site | → Callee | Form |
|---|---|---|
| `dev-studio.ts:284` | `Star` (`star.ts:326`) | 3-arg — silent |
| `dev-studio.ts:310` / `:328` / `:343` | `DevContainer` `setAppVersion` (`:539`) / `bootAndApply` (`:485`) / `applyChanges` (`:467`) | 3-arg — silent |
| `nebula-client.ts:1616` / `:1677` | `DevStudio` (`:372` / `:472`) | 3-arg — silent |

| `dev-studio.ts:897` (`#recordTurn`) | `Galaxy.recordTurn` (`:222`) | 3-arg — silent; **the one hop that crosses UP a tier** |

- **The invariant that keeps the same-tier/downward bulk safe, currently unstated anywhere:** each targets a node the origin's own `{u}.{g}.dev` pattern already covers. State it; do not let it be rediscovered.
- ⚠️ **`dev-studio.ts:481` is the cheapest early warning during the build** — it is the single place an over-tight predicate surfaces *loudly* rather than silently. Watch it first.
- **The upward hop** — `#recordTurn` → `Galaxy.recordTurn`, whose safety today rests on a *comment* (*"the origin user is a galaxy admin…"*). That premise **dies at identity-mint Phase 1**: a star-tier admin's `recordTurn` is then **correctly denied**. Expected-and-correct, not a regression to chase — the corpus gap is bounded and the hop disappears at the collapse ([nebula-galaxy-collapse-and-chat.md:144](../nebula-galaxy-collapse-and-chat.md)). ⚠️ **Mechanism, so nobody instruments the wrong seam:** 3-arg sets `response={kind:'discard'}` and the `@mesh` guard runs *post-ack*, so the throw is logged **framework-side on the Galaxy end** ([lmz-api.ts:820-825](../../packages/mesh/src/lmz-api.ts)) and never reaches `#recordTurn`'s own try/catch — which can only see a synchronous dispatch error.
- **The `delete-scope` → `teardown()` fan-out** — safe because [nebula-auth-registry.ts:737](../../packages/nebula-auth/src/nebula-auth-registry.ts) breaks the prune-up loop on `#hasAdminOverScope`. That invariant lives in *another package*; state it in the annotation.

⚠️ **Do NOT "fix" this by tightening `enforceScopeReach`'s tenant branch instead.** Admission of a descendant's `aud` to an ancestor DO is a separate, possibly-intended behavior; narrowing it would change non-admin reach as a side effect. The defect is authority, not admission — fix it where authority is decided.

## Decisions
| Decision | Rejected alternative — why |
|---|---|
| The stored subscriber bit persists the **confined verdict**, computed at subscribe time | Confining at push time — **infeasible**, not merely worse: the live JWT is gone at push time and only the 0/1 bit was ever stored, never the pattern ([subscriptions.ts:165](../../apps/nebula/src/subscriptions.ts) and its preceding comment). |
| **Keep the column name `accessAdmin`; fix the JSDoc instead** | Renaming to `adminBypass` — the blast radius is **test-side and invisible to both type-check and the sweep grep**: [test-apps/baseline/index.ts:217](../../apps/nebula/test/test-apps/baseline/index.ts) hand-rolls its *own* `CREATE TABLE Subscribers` (it does not replay migrations, so a rename resurrects a stale schema and breaks ~10 test files), plus `inspectSubscribers`/`inspectQuerySubscribers` SELECT it by name and `subscriber-list.test.ts:261`'s `not.toContain('accessAdmin')` would go vacuous. The `idMonotonicInc: 3` ceremony would also preserve data this milestone **wipes** ([collapse:309](../nebula-galaxy-collapse-and-chat.md); `Subscribers` is already DROPped on every ontology install) — and [identity-mint:38](../nebula-auth-identity-mint.md) invokes that same wipe to skip migration work, so a rename here would take the opposite stance on the same wipe. Fix the JSDoc where the lying name actually misleads: both row types **and** `evaluatePermissions` (`dag-tree.ts:422-441`, which documents the operand as the raw claim). |
| Store-time confinement introduces **no NEW staleness axis** — it is **monotonically narrowing** | Claiming *no* staleness at all, or waving at ADR-013. The verdict has three operands, and each is answered: (1) **`admin`** — mutable via `setIdentityAdmin`, but that demotion axis is **unchanged from today's raw bit**, pre-existing not introduced. (2) **host instance name** — immutable for the DO's lifetime. (3) **`authScopePattern`** — a *scope-set*, exactly what ADR-013 says must resolve live; it derives from the identity's immutable issuing scope (`buildAuthScopePattern(record.universeGalaxyStarId)`, [worker-token.ts:224](../../packages/nebula-auth/src/worker-token.ts); `setIdentityAdmin` touches only `isAdmin`), and a `/delegated-token` narrowing lands on a per-`clientId` row consumed per-connection, where narrower is correct. **The property that reconciles it with ADR-013:** the stored value is a strict conjunct-*subset* of today's stored `claims.access.admin`, so drift can only ever go 1→0 (under-privilege), never 0→1. The ADR-013 hazard — stale authz granting more than it should — is structurally absent. |
| Fold the stored bit into Phase 2, not its own phase | A separate decide-phase — same plumbing (one thunk, `ResourceDataPlane` is the sole construction site) and the same arming moment; splitting ships the live path armed and the stored path un-armed. |
| `#hasAdminOverUniverse` folds into the shared predicate | Treating it as deliberately narrower — provably equivalent on its input domain: its sole caller ([:356](../../packages/nebula-auth/src/nebula-auth-registry.ts)) passes a single dot-free segment, and on single-segment targets `matchAccess` reduces exactly to its three hand-rolled branches. |
| Both phases test at **unit** level, against synthetic non-leaf host names | Integration-only — §B has no non-leaf host until the collapse, and `star.ts`'s deny case is unbuildable on any real Star, so an integration test would be **green by construction**. The deferred integration assertions are handed off as named `it.skip`s (Phase 2). |
| **Absorb the baseline-lane re-grounding as Phase 0** and test the §A principal via a real `/delegated-token` login | `createNebulaTestToken` (ADR-009 rung 3) — cheaper and precedented in this lane, but using a **client-side mint** to test a guard that *reads minted claims* is the mis-grounding ADR-009 exists to prevent. The lane also has to be re-grounded eventually; doing it here costs one extra commit and unblocks 36 files. |
| **`/delegated-token`'s `:324` gate is annotated, not changed** | Tightening it — the gate is an **upper** bound and correct; *narrowing is the feature*, not the bug (`buildAuthScopePattern(activeScope)` deliberately binds the mint to the requested scope, and its test asserts exactly that). The defect is entirely downstream: the guards read the admin bit without the scope. After the confinement the vector is closed with **nothing residual** — `matchAccess('{u}.{g}.*', '{u}')` is false, so the delegated token is denied on the ancestor. Changing `:324` would either break delegation or add a redundant check. **Annotate so nobody later reads "upper-bound-only" as a gap and "fixes" it.** |

**Not decided here, deliberately:** whether a *demoted* admin's already-stored verdict should be invalidated. Pre-existing (it exists today with the raw bit), a different defect, no present consumer, and partly covered by the D16 reconnect self-heal at [nebula-client.ts:858-863](../../apps/nebula/src/nebula-client.ts). → [backlog.md](../backlog.md) § Nebula Auth.

## Phases

0. **Re-ground the `apps/nebula` baseline lane on the no-mint login.** ✅ **DONE 2026-07-20 — 334/334 tests, 54/54 files green** (was 0 login-dependent tests passing). Pre-existing breakage, not caused by this task — but Phase 1's tests run in this lane, and ADR-009 says the principal under test should come from a **real login**, not a client mint.
   - **It was NOT a field rename.** That was the *surface*: three `magic_link` destructures vs the endpoint's `magicLinkUrl`. Fixing it only moved the failure to `401` on refresh. The real break is structural and changed the lane's auth model:
     - `requestMagicLink` **never mints** (only the bootstrap email at `nebula-platform` does). An identity must pre-exist: `claim-universe` (founder, `isAdmin: true`) or `invite` (member, `isAdmin: false`).
     - `claim-universe` takes a **dot-free universe slug**, so a founder admin can only ever be minted at universe tier — pattern `{u}.*`. **There is no "star-level admin" tier and no way to have two founders in one universe.**
     - The refresh cookie is RFC-6265 path-scoped and `@lumenize/testing`'s `cookieMatches` implements it correctly (its own comment: *"`/auth/acme` must NOT match `/auth/acme.crm.tenant`"*). **Verified by spike:** refresh at universe authScope + star activeScope → 200 (`aud={u}.app.tenant`, `pattern={u}.*`, `admin=true`); the same cookie against the star path → **401**.
     - ⇒ every founder fixture authenticates at the **universe**, with the star as `activeScope`.
   - 🔶 **INTERIM — the principal is wrong for ~30 fixtures, deliberately.** A fixture asking for "an admin at this star" receives a **universe admin** (`{u}.*`), because `claim-universe` is the only founder-minting path that exists today. Star founders are the **primary** use case and must NOT be universe admins. **Retiring trigger: [nebula-star-founder-provisioning.md](../nebula-star-founder-provisioning.md)** — which mints a founder at the star with an **exact-star** pattern (NOT [nebula-auth-identity-mint.md](../nebula-auth-identity-mint.md); that mints star-tier admins by *invite* — same principal shape, different provenance, and it does not close the self-signup case).
     ⚠️ **Ordering is a security constraint, not a preference: confine → star-founder → re-ground.** A star founder holds an exact-star pattern, so *before* this task's confinement it is admitted to its Galaxy and Universe by `enforceScopeReach`'s tenant branch and treated as admin there (§A). Landing star founders first would ship that escalation to **every self-signup tenant**.
     **To keep the re-grounding to one helper body instead of ~30 call sites, split by INTENT before star-founder lands** — `adminClientAt(scope)` (whatever admin legitimately governs `scope`) vs `universeAdminClient(universe, activeScope)` (specifically a `{u}.*` admin). Both mint a universe admin today; after star-founder they diverge, and only the helper body changes. The three fixtures re-anchored in Phase 0 (`guards`, `dag-tree`, the `scope-isolation` exact-star anchor) are `universeAdminClient` — correct under **both** models.
   - **Helper split** ([test-helpers.ts](../../apps/nebula/test/test-helpers.ts)) — the model is now explicit in the API, not implied by a scope string:
     `universeOf` · `claimUniverse` (409-tolerant: one founder backing several clients) · `bootstrapAdmin` (claims, falls back to login) · `foundAndLogin` · **`createAuthenticatedClient` = founder** (derives + claims the universe, so ~125 call sites needed no edit) · **`createInvitedClient`** = already-minted member · **`createPlatformAdminClient`** = the bootstrap `*` admin.
   - **Fixtures that needed judgment, not a sweep** (the hazard flagged before starting — each would otherwise have gone green while testing nothing):
     - *exact-star branch-(e) anchor* (`scope-isolation`) — an exact-star `authScopePattern` is now mintable **only by invite**, so the caller became an invited member; the reach clause is skipped because it is non-admin rather than because an admin pattern missed. Added `expect(payload.access?.authScopePattern).toBe(starA)` so the fixture can't silently widen. The exact-pattern-**admin** variant needs `/delegated-token` → covered by Phase 1.
     - *two-admins-in-one-universe* (`guards`, `dag-tree`) — unmintable. Both became one founder whose second client holds **aud = the universe** while acting on a Star, so admission comes from the *reach* branch — a sharper test of "universe admin reaches a descendant Star" than the original.
