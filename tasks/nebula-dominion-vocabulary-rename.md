**Status:** Active child, **first of four** in the passage/dominion sequence — ahead of [nebula-passage-dominion-from-scope.md](nebula-passage-dominion-from-scope.md), [nebula-registry-route-guards.md](nebula-registry-route-guards.md) and [nebula-invite.md](nebula-invite.md). From here: `/review-task` Stage 2, then `/build-task`.

> ✅ **Not wipe-gated, not invite-gated, gated on nothing.** ⚠️ **An earlier banner said WIPE-WINDOW-GATED and that was wrong twice over** — it assumed a migration was needed at all, and it treated the wipe as a *deadline* (rename now or pay later) when the wipe is an *enabler*. **No migration is needed anywhere** (§ *Phase 2*). This file goes first for the two reasons in § *Why this is its own file*, not for a schedule.

**Objective — every identifier that names dominion says `dominion`, and nothing else changes.** No behaviour moves, no claim changes shape, no predicate gains or loses an argument. A reviewer should be able to check this file's diff by reading names, and a type-check should catch everything except three DDL strings, one test assertion, and prose.

## Why this is its own file

**Because "renames are free" is exactly the belief that hides them inside a bigger diff.** The three files after this one each change real behaviour — a claim's shape, a route's guard, a mint's authorization. Renames landing in those diffs are indistinguishable from the behaviour changes at review time, and this repo has the receipt: the `isAdmin` → `scopeAdmin` sweep touched **66 files**, and two packages (`packages/auth`, `packages/mesh`) keep their own unrelated `isAdmin` that a repo-wide replace would have broken — **the mesh one silently**.

Two things it buys:

- **The reviewable property is stated and checkable:** nothing here changes what any code *does*. A diff hunk that changes control flow is a defect in this file, by definition. ⚠️ **That property is only as good as its instruments** — see § *Acceptance criteria*, where two greps were structurally blind to the symbol this file is named after.
- **It settles the vocabulary before anything designs against it.** [nebula-invite.md](nebula-invite.md) currently parks a naming decision — its wire field is `invitees[].isAdmin` while the column is `Memberships.scopeAdmin` — on the grounds that *"deciding it here would be designing this endpoint from another task's cleanup."* After this file the cleanup has landed and that decision costs one line.

## Context and current state

`isAdmin` → `scopeAdmin` already shipped 2026-08-07 (at rest and in flight, 66 files, type-check green). This file finishes the same job for the *verdict* names, which lagged.

The vocabulary itself is settled: **`dominion`** and **`passage`** are reserved terms defined in [ADR-015](../docs/adr/015-passage-and-dominion.md) § *Terminology*. They replaced `authority` and `admission` on 2026-08-09 because both general words carried four meanings apiece and the ambiguity had shipped real bugs. ⚠️ **`reach` is not their umbrella noun** — it stays a verb, and MUST NOT be used as a noun for either verdict.

⚠️ **No deploy happens between now and the pre-alpha wipe**, and local and test storage are created from scratch under vitest and `wrangler dev` ([nebula-pre-alpha.md](nebula-pre-alpha.md) § *The wipe is a CLOSING WINDOW*, item 5: *"the constraint stands that there is no deploy between the rewrite and the wipe"*). ⇒ **No storage anywhere will ever run pre-rename code against a post-rename schema**, which is why § *Phase 2* needs no migration and this file needs no wipe gate.

**Missing:** the guards and helpers are still named for the **bit** or for the **deleted general word**, while the predicate they delegate to is about to be named for the **verdict**. That gap is the translation the reader carries, and this layer is where a carried translation becomes a security hole.

## Design intent, constraints, and future state

### The three tiers govern which name a symbol gets

A **structural fact** gets a literal name · a **verdict** gets a reserved word · **data** keeps its field name. That is the rule; this file applies it only where doing so changes no behaviour.

⚠️ **Counts below are dated samples, not inventories** (`tasks/README.md` § *Inventories*) — re-run the greps rather than trusting them.

⚠️ **FOUR things look like they belong here and MUST NOT be taken.** Each would smuggle a behaviour change into a file whose whole claim is that it has none:

- **`matchAccess` → `isAtOrAbove` / `isAtOrBelow` is NOT a rename.** A glob matcher becomes a hierarchy predicate — different grammar, different answers on colliding segment names. It belongs to [nebula-passage-dominion-from-scope.md](nebula-passage-dominion-from-scope.md).
- **The six `const pattern = …` locals are correctly named TODAY.** They hold `claims.access.authScopePattern`, which *is* a pattern. They only become misnamed once the claim carries a scope, so renaming them here would make them wrong for the duration of two files.
- **`hasPassage` cannot be born here.** It is `isAtOrBelow ∨ dominion`, and `isAtOrBelow` does not exist yet. ✅ **This file makes its absence VISIBLE rather than fixing it** — after the rename, `requirePassage` is a function computing passage inline that nothing else can call, which is the next file's finding stated in one name.
- 🚨 **REFUSAL STRINGS AND ERROR MESSAGES ARE OUT** — added 2026-08-11 by the Stage-1 panel, and the most likely accidental inclusion, because this file's own motivating sentence applies to them verbatim. `requireAdmin` throws `'Admin access required'` and an interpolated `` `Admin access required for ${name} — your admin scope is …` ``; `worker-token.ts` returns the same body. **Five test assertions pin those strings** (`guards.test.ts`, `dev-star-data-lifecycle.test.ts`, `dev-studio.test.ts` ×3), so rewording them reds five tests and falsifies 🔒 *Nothing changed behaviour*; `packages/auth` carries an identical string that must not move; and the identifier grep cannot see a string sweep at all. The interpolation changes anyway when the claim changes shape ⇒ the reword belongs to [nebula-passage-dominion-from-scope.md](nebula-passage-dominion-from-scope.md).

### Constraints

- **[ADR-015](../docs/adr/015-passage-and-dominion.md)** — the definition home for both reserved terms. This file does not amend it and does not exercise it; it adopts its vocabulary. ⚠️ **Ratification is Larry's ad-hoc call and is gated on nothing** — no phase here owns it, and none may.
- **[ADR-007](../docs/adr/007-shared-node-security-core.md)** — one predicate expresses the model. This file does not add or remove a caller; it renames the one that exists and deletes one pass-through wrapper.
- **`.claude/rules/coding-style.md` § *Guard naming*** — the durable home for the three-tier rule and the `require*` = THROWS / `*Guard` = RETURNS contract, moved there 2026-08-11 so it outlives these four task files. ⚠️ **Do not restate its argument here** — cite the section.
- ⚠️ **`packages/auth` and `packages/mesh` MUST NOT have their own `isAdmin` swept.** It is a *different* bit (auth's `Subjects` column, and a flat top-level claim mesh mints for auth's gate). A repo-wide replace breaks both, **the mesh one silently** — which is why the 2026-08-07 sweep was scoped by hand. ⚠️ **This is NOT "do not touch those packages"** — Phase 1 must touch one line of `packages/mesh`; see there.
- ⚠️ **The Data-plane's `admin` permission is NOT renamed.** It is one of a symmetric triple (`CHECK(permission IN ('admin','write','read'))`), so renaming it drags `resourceWrite` and `resourceRead` along for no gain. This file renames the **Registry-scope** bit's verdicts only.

## Decisions

| Decision | Rejected alternative — why |
|---|---|
| **The renames land in their own file, first** | Folding them into the behaviour changes — a rename inside a diff that also moves control flow is unreviewable as a rename, and this is a few hundred call sites of mechanical noise laid over the changes that must not be gotten wrong. |
| **`enforceScopeReach` → `requirePassage` lands HERE**, though its input changes later | Holding it until the input changes — the body already computes passage across both arms, so the new name is true on arrival, and holding it means the next file's diff carries a rename on its most load-bearing function. |
| **`require*` means THROWS, repo-wide; a step that RETURNS a `Response` is `*Guard`** | Keeping `enforce` vs `require` as the carrier — it points the wrong way (`require` throws in Solidity and in `assert`, and at every one of this repo's own `requireAdmin` / `requirePermission` sites) and would rename all of them to `enforce*` to say what `require*` already says. **Homed in `coding-style.md`**, because it binds code written long after these files archive. |
| **`requireDominionHere`, not `requireDominion`** | The bare form — dominion is a **two-place relation** (ADR-015), and this is the family's only object-less member: `requirePermission(nodeId, tier)` names its object, `hasDominionOver(access, node)` cannot be read without one. "Require dominion" is one word from *the bare bit is dominion*, the failure this rename exists to prevent. Today's JSDoc already compensates in prose (*"over the node this call is running on"*), which per `calibration.md` §5 **is** the rename signal — and the sibling [nebula-registry-route-guards.md](nebula-registry-route-guards.md) spells its operand out for exactly this reason. `Here` is fixed by construction (the callee instance from `callContext`), so it cannot be passed wrong. |
| **The column rename is a DDL EDIT IN PLACE — no migration, on either table** | A numbered `ALTER TABLE … RENAME COLUMN` entry. ⚠️ **Reversed 2026-08-11 once the premise was checked.** Three facts kill it: no deploy happens before the wipe; local and test storage are created from scratch; and `clear()` **replays the migration DDL inline** on every version-changing ontology install, so a rename entry would create the table with the old name and immediately rename it — **forever**. |
| **`accessAdmin` splits into `dominionAtSubscribe` (the column) and `hasDominion` (the parameter)** | One name for both — `AtSubscribe` asserts subscribe-time confinement, which `evaluatePermissions`' own JSDoc **disclaims** for its parameter. One name would stamp a false security claim, in the file whose thesis is that it settles the vocabulary. |
| **`#hasAdminOverScope` is deleted, not renamed** | Renaming the wrapper forward — it is a one-line pass-through to the shared predicate under the same name, with one caller. `calibration.md` §2: make the class impossible rather than carrying it. |

## Acceptance criteria

- 🔒 **No identifier still names the old model.** `grep -rnE '\b(requireAdmin|accessAdmin|enforceScopeReach|hasAdminOver[A-Za-z]*)\b' apps/nebula/src apps/nebula/test apps/nebula/harness packages/nebula-auth/src packages/nebula-auth/test packages/mesh/src` returns nothing. ✅ **Executed 2026-08-11: returns 297.** 🚨 **The path list is load-bearing and a `src`-only form was BLIND to more than half of it** — 140 under `src`, **296** once tests are included, and the ~72 comment-only hits are reachable by no other instrument: an LSP rename never touches a comment, and 🔒 *No RETIRED term survives* is self-excluding for them, because a file no rename touches never enters `git diff --name-only`. ⚠️ **This is the Stage-1 blocker's defect in the PATH dimension rather than the regex one, in the same instrument** — which is why the criterion now states its scope as the thing to check rather than a directory that reads like a reasonable default. 🚨 **The `hasAdminOver[A-Za-z]*` form is load-bearing, and the earlier bare `hasAdminOver` alternative was STRUCTURALLY BLIND** — `\b` after the alternation demands a word boundary between `r` and `S`, so it could never match `hasAdminOverScope` / `…Universe` / `…Galaxy`. Measured: the old form returned **105 with and 105 without** that alternative, while 38 such lines exist. **Phase 1 could have shipped with the shared predicate entirely un-renamed and this gate would have gone green** — and it carried an ✅-executed annotation, which is what stopped anyone re-running it. ⚠️ **Running a command proves it EMITS output; it does not prove the output COVERS what the criterion claims.**
- 🔒 **No standing-guidance statement cites a symbol this file deletes.** `grep -rn 'hasAdminOver[A-Za-z]*\|enforceScopeReach\|requireAdmin\|accessAdmin' docs .claude tasks website/docs` — every hit gets a verdict; **frozen `tasks/archive/` is exempt**. ⚠️ **The same blindness was present here and is fixed**: spelled in full, it missed `hasAdminOverUniverse` / `…Galaxy`, both deleted by Phase 1 and both cited in **active** files (`tasks/backlog.md`, `tasks/nebula-invite.md`). ⚠️ **Guidance citing a deleted symbol is worse than guidance citing a deleted model**: the reader greps, finds nothing, and cannot tell whether the rule is stale or they are looking in the wrong place. ⚠️ **Do not trust a "known homes" list — the one that stood here was FALSE.** Run it. A 2026-08-11 sample outside this file and its three siblings: `.claude/rules/mesh.md`, `security.md`, `calibration.md`, ADR-015, ADR-007, `website/docs/nebula/auth-flows.md`. ⚠️ **"Standing guidance" is the CLAUDE.md list** — it includes `.claude/skills/*/SKILL.md` and **agent memory**, neither reachable by that grep, and memory is the worst of them: it loads every session unprompted and nothing type-checks it.

## Phases

Two phases. Each leaves the suite green.

### Phase 1 — The verdict names, in code

`hasAdminOverScope` → `hasDominionOver` · `requireAdmin` → `requireDominionHere` · `hasAdminOver{Universe,Galaxy}` → `hasDominionOver{…}` · `enforceScopeReach` → `requirePassage` · `#hasAdminOverScope` **deleted**, its one caller pointed at the shared predicate. Exported from `index.ts` and `testing.ts` exactly as before — ⚠️ **the export surface does not narrow**; `testing.ts` re-exports the predicate precisely so a test never re-inlines the `scopeAdmin ∧ scope-at-or-above` conjunction by hand.

⚠️ **Use an LSP / `ts-morph` rename, then verify with a BARE-identifier grep** (`workflow.md` § *Symbol renames*). A quoted-literal replace silently misses member/type-position access (`x.Old`, `rels.Old.field`) and doc comments, which survive, compile, and surface as a runtime failure — that exact defect bit the `Turn` → `Message` rename **twice**.

⚠️ **One line in `packages/mesh` must be touched, and the earlier instruction for it was WRONG IN BOTH DIRECTIONS.** [`lmz-api.ts`](../packages/mesh/src/lmz-api.ts)'s `__handleResponse` JSDoc reads *"the response leg was **rejected at admission** (e.g. `enforceScopeReach`, D5)"*.

- ✅ **Re-word only the clause naming OUR symbol** — e.g. *"rejected during admission (the D5 scope gate, now `requirePassage`)"*.
- 🚨 **Do NOT rewrite `admission` to `passage` here.** In mesh it is that package's **own pre-ack dispatch-phase vocabulary**, not ADR-015's boundary verdict — 16 hits in this file alone, including the `// --- ADMISSION (pre-ack)` banner, `onBeforeCall` documented as *"Authorization hook run at admission"*, and the runtime string `'Mesh call rejected at admission'`. Our guard is **one example** among version/callContext/identity checks on that path, so renaming it asserts a refusal reason that may be false and leaves one sentence inconsistent with fifteen siblings. ADR-015 retires the word **as the name of either concept**, and preserves other senses.
- ⏳ **`D5` is a task-file handle in source and is NOT this file's to convert** — the line is mesh's, the handle is a mesh task file's, and guessing at what `D5` meant is worse than leaving it. Note it; the changed-files criterion is scoped so this does not block.

⚠️ **The genuine retired-term work is in OUR files, and the criterion is what finds it** — `nebula-do.ts` glosses the verdict as **"(admission)"** inside `requireAdmin`'s own JSDoc, and uses **"reach" as a noun a dozen times** in and around `enforceScopeReach`'s JSDoc, so `requirePassage` would otherwise ship documenting itself in the noun § *Constraints* forbids.

**Criteria:** 🔒 *No identifier still names the old model* — ⚠️ **scoped form for this phase: drop `accessAdmin` from the alternation**, which is Phase 2's work and cannot pass here · 🔒 *No standing-guidance statement cites a symbol this file deletes* — every symbol except `accessAdmin` dies here, so it belongs to this phase rather than the last · 🔒 *No RETIRED term survives in prose this work touches* · 🔒 *Nothing changed behaviour* · 🔒 *No `isAdmin` in the sibling packages is renamed* · *The data-plane permission tier is untouched*.

### Phase 2 — The column and its parameter

**`accessAdmin` → `dominionAtSubscribe` (the column) and `hasDominion` (the parameter).** ⚠️ **This is THREE one-line DDL edits and NO migration** — the shape was reversed on 2026-08-11 (§ *Decisions*), and the reversal deleted an entire migration-runner design rather than fixing it.

- **The three DDL sites**, all edited in place:
  - `subscriptions.ts` — migration **id-2**'s SQL (`ALTER TABLE Subscribers ADD COLUMN accessAdmin …`). ⚠️ **Edit id-2 in place; do NOT add an id-3 rename entry.** `clear()` replays the list inline on every version-changing ontology install (`star.ts` → `clearSubscribers()`), so an id-3 would create the table with the old name and rename it on every install, forever.
  - `query-subscriptions.ts` — the inline `CREATE TABLE IF NOT EXISTS` in `#createSchema()`. ⚠️ **It needs NO migration list.** The earlier plan to give it one would have broken `clear()`: that method does `DROP TABLE` then `#createSchema()`, so a runner whose marker was already at high-water would match nothing, write nothing, throw nothing — and the next `SELECT` would hit `no such table`.
  - 🚨 **`test-apps/baseline/index.ts` — `clearSubscribersForTest()` hand-rolls its OWN `CREATE TABLE Subscribers` and replays no migrations.** Found by the Stage-1 panel. It is a **SQL string literal**, so neither an LSP rename nor any `src`-scoped grep reaches it. This is the site the archived decision named as its reason for rejecting the rename, and missing it resurrects a stale schema across ~10 test files.
- 🚨 **One test assertion goes VACUOUSLY GREEN and must be inverted.** `subscriber-list.test.ts` asserts `expect(s).not.toContain('accessAdmin')`. After the rename that passes **trivially, forever** — the rename itself manufactures a criterion that cannot fail. Point it at the new name. ⚠️ **Invisible to every instrument in this file**: not an identifier, not in the `src` grep, green either way.
- **The parameter takes a different name.** `DagTree.evaluatePermissions(…, accessAdmin)` → `hasDominion`, with its call sites in `resource-data-plane.ts` and the JSDoc/prose mentions in `dag-tree.ts`, `query-hash.ts` and `nebula-client.ts`. ⚠️ **Not `dominionAtSubscribe`** — that name asserts a confinement this method's own JSDoc disclaims.
- ⏳ **Task-file handles in the two changed files** — `D16` ×5 in `subscriptions.ts`, plus `D16`/`D13`/`D2`/`D4` ×6 in `query-subscriptions.ts`. `workflow.md` forbids them in source; each becomes a clause of prose or an ADR citation. ⚠️ **Only two sit on lines the rename touches** — the rest are prose the sweep would sail past, so "the rename touches the line anyway" justifies a fraction of this and must not be read as covering it.

**Criteria:** 🔒 *No identifier still names the old model* (full form, including `accessAdmin`) · 🔒 *No task-file handle survives in the files this work changes* · 🔒 *Nothing changed behaviour* · 🔒 *No RETIRED term survives in prose this work touches*.
