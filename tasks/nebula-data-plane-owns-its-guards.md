# Every Resources guard lives in the Resources plane

**Status:** Pass 1 — design intent only, phases NOT written. Scoped to the two hosts that compose the plane today, the **Galaxy and the Star**. The Profile absorbed here on 2026-09-08 was cut back out on 2026-09-22 — it is a consequence of this guard model rather than part of establishing it, and now follows in [on-hold/nebula-profile-storage.md](on-hold/nebula-profile-storage.md). **The Resources leg of the security-legibility work**, after `docs/vision/auth.md`, [ADR-015](../docs/adr/015-passage-and-dominion.md)'s passage/dominion vocabulary, and the Registry routing rewrite that put its guards in one readable table. **Sequenced AFTER [nebula-galaxy-collapse-and-chat.md](archive/nebula-galaxy-collapse-and-chat.md)** (decided with Larry 2026-08-23) — § *Transition* says why, and names the one interim that task carries in the meantime. Judge this as a change to how the access-control model is reasoned about, not as a refactor.

**Objective — answering *"who is allowed to do this to a resource?"* takes reading one bounded region of code.**

**Three goals, in the order they matter:**

1. **The answer stops being split across the host and the plane.** Today it is in seven places: `requirePassage` in `onBeforeCall`, 5 `requireDominionHere` decorators, **24 identity derivations inside host method bodies**, 5 permission calls inside `Resources`, 3 inside `Subscriptions`, none in `QuerySubs` (which filters at delivery instead), and 30 sites in `DagTree` including the dominion short-circuit. Seven places is not an audit, it is an archaeology. ⚠️ **Every tally here MUST be re-run by the phase rather than inherited, with the pattern ANCHORED** — `grep -rcE '^\s*@mesh\(requireDominionHere' apps/nebula/src/*.ts` and `grep -cE 'callContext\.callChain' apps/nebula/src/star.ts apps/nebula/src/galaxy.ts` (measured 2026-09-21: 5, and 14 + 10). The dominion number has now been wrong twice in this file for the SAME reason both times — an unanchored pattern counts the JSDoc prose that discusses the decorator alongside the decorator itself, and both hosts discuss it at length.
2. **No guard sits where a reader would not think to look.** Those derivations are not plumbing. `clientId` decides whose subscriber row is written and whose row a delete removes, and the code says so: *"`clientId` is supplied by the Handler-1 wrapper from `callChain[0]` (NEVER a param), so a client can only drop its OWN row."* That is a guard, it lives on the host, and it is copied per host — `unsubscribe` matches statement-for-statement across `star.ts` and `galaxy.ts` (verified byte-identical 2026-09-21).
3. **Every name answers "what is this?" without being asked, starting with the plane itself — it is the RESOURCES plane, never the "data plane"** (Larry, 2026-08-23: *"what we will forever more call the resources plane"*). `Resources` today is a 683-line temporal storage engine *inside* a thing called `ResourceDataPlane`, and `QuerySubs` opens by calling itself *"a near-clone of `Subscriptions`"*. Names you have to ask about are a model you cannot hold.

⚠️ **To decide here — goal 3's two remaining renames, because a phase must not invent them.** The 683-line storage engine has to give up `Resources` to the plane and has no successor named; the merged registry has none either. **Proposed, each taking the name of the table it already owns:** `Snapshots` for the storage engine — its rows are ADR-004 snapshot sequences and `Snapshots` is already the table — and `Subscribers` for the merged registry, already its table, and the four it replaces are all subscriber rows. Rejected: `TemporalStore` and `SnapshotStore`, new vocabulary for a table that already has a name; `History`, because ADR-004 calls history the substrate rather than the engine; and `Subscriptions` for the merge, since it is one of the four being merged and would read as the survivor rather than the union.

The sections below give the guard model these goals imply, the one consequence that sets how far the task reaches, and the question that has to be answered before phases.

## Context and current state

**Built already, and what becomes of each part:**

- **`ResourceDataPlane`** — one class, composed by a host with a single `new`, holding five sub-capabilities. **Adapted**: it becomes the plane itself and takes the name, so a host reads `#resources = new Resources(...)`.
- **`Resources`** (683 LOC) — the **temporal storage engine**: Snodgrass snapshot sequences over the host's SQLite, calling `DagTree.requirePermission` at 5 sites. **Adapted**: keeps its job, gives up its name.
- **`DagTree`** (528 LOC) — nodes, edges, grants, resolution, and the `hasDominionOver` short-circuit. **Carried over unchanged**, and it is the model the rest should match: its guards are already in the methods they protect.
- **`Subscriptions` (263) · `QuerySubs` (204) · `QuerySubscriberListSubs` (91) · `TreeSubscriptions` (69)** — **FOUR registries of one kind, not three** (corrected with Larry 2026-09-22; the file said three until he asked why the tree channel was keyed differently, and it is not). **Adapted into one** — and a fifth, `ReloadSubscriptions`, is DELETED rather than merged (below).  Every one of the five carries the identical triple `clientId · subscriberBinding · subscribedAt` — the delivery address — and they differ on two orthogonal axes: an optional TOPIC column, and an optional AUTHORIZATION identity.

    | Registry | PRIMARY KEY | Topic | Authz identity |

    | `QuerySubscribers` | `(queryHash, clientId)` | `queryHash` | `sub` + `profileId` + dominion bit |
    | `QuerySubscriberListSubs` | `(queryHash, clientId)` | `queryHash` | none |
    | `TreeSubscribers` | `(clientId)` | — | none |

## Design intent, constraints, and future state

**The contract, in three tiers.** A Resources operation passes exactly three checks, each in one place. **The host's `onBeforeCall` requires passage and decides nothing else.** **The facade a gate returns supplies what the caller may not state** — the client's own id on the request leg, a dead client's id on the response leg. **The plane method below holds permission and ownership**, and is reachable from no wire at all. So a forgeable parameter survives on the plane, harmlessly, because nothing outside can name the method that takes it.

**Two gates, and exactly one door** (the door settled with Larry 2026-08-23; the second gate 2026-09-21). A host composes the plane and exposes two accessors that do nothing else:

```ts
@mesh() resources()  { return /* … */ }   // the DOOR — request leg
resourcesResults()   { return /* … */ }   // response leg ONLY — no @mesh(), deliberately
```

Each returns a **narrow facade** over the plane rather than the plane itself — § *The surface, allocated* allocates every method and is where that shape is argued. ⚠️ **The two gates are told apart by the LEG, never by "where the caller id comes from."** That reading is tempting and false: `onInviteResult` takes an `InviteSummary`, not a dead client's id, and a request-leg push supplies no caller id at all. The leg is true of every member; identity is true of most.

**`resourcesResults()` is not a second door.** `ocan/execute.ts` checks the allowlist on a chain's FIRST apply and latches, so a bare accessor is refused as an entry op exactly as a bare method is. `__handleResponse` runs the same path at `requireMeshDecorator: false`, so a fire-back consults no allowlist while `onBeforeCall` still requires passage. So a gate with no decorator is response-open and request-closed — and confers that on everything behind it. **There are two legs, so there are two gates**; a third has nothing to reach. ⚠️ **"Response leg" means a FIRE-BACK, not any result-shaped call.** `svc.broadcast`'s flat branch fires back 4-arg into `__handleResponse` and is the branch pinned ON; its tier branch forwards 3-arg through `__forwardBroadcastResult`, which is an ordinary REQUEST and so meets the allowlist. A bare accessor is refused there, by design and identically to the request leg.

⚠️ **The missing decorator is load-bearing and invisible.** Adding `@mesh()` to `resourcesResults()` — the tidying reflex, since every other gate has one — opens every continuation target to any logged-in browser in one edit. It replaces the three invite-forward notes that say it in prose today, so it owes a test asserting the ABSENCE — and **`getMeshGuard` cannot see one**: `mesh-decorator.ts` sets `MESH_GUARD` only when a guard argument is passed, so it reads falsy for a bare `@mesh()` and an undecorated method alike. The assertion is `expect(isMeshCallable(Galaxy.prototype.resourcesResults)).toBe(false)`, which depends on no frozen list, and the mutation that reds it is adding the decorator. (`star.ts`'s `onOntologyPulled` note stays put — an ontology-install fire-back, not a Resources op.)

**`@mesh() dagTree()` does NOT survive beside it.** `DagTree` is the org and permission tree — `createNode`, `addEdge`, `reparentNode`, `setPermission`, `revokePermission`, `requirePermission`, `evaluatePermissions` — so it is part of the resources plane by any reading, and a capability inside the plane does not get its own entrance. It is reached as `resources().dagTree.setPermission(...)`: **no parens on `dagTree`, it is a getter**, and a chained `apply` on it throws `TypeError: … is not a function` from `ocan/execute.ts`. The sweep is the client's ten `orgTree` mutators plus the baseline test-app's twenty tree wrappers and two test files — no harness scenario reaches the tree directly, they all go through `client.orgTree.*`. Mechanical, `calibration.md` §3(c) prices the test half at roughly zero, and `/refactor-efficiently` makes it cheap. Larry: *"If we have two, why not three? why not 10?"* A second door is not a smaller version of the mess; it is the first instance of it.

**Seen from the client, this collapses many ways into one.** Today `nebula-client.ts` reaches the host through a distinct continuation per entry — `ctn<Star>().transaction(...)`, `.subscribe(...)`, `.subscribeQuery(...)`, and the rest of the ~16 — plus the chained `dagTree()` gate. After this task every one of them is the same shape, `ctn<Host>().resources().<op>(...)`: one way to reach the plane, from every caller, and a new client method cannot invent a second.

**The one thing that legitimately stays outside is an INJECTION, which is why it stays clean.** Ontology acquisition is host-specific — Star resolves an installed version through `#ensureFacet()`, the Galaxy through `chatOntology()` — and it arrives as a **required** constructor argument returning `{ version, facet, relationships }`. A required injection is a seam with one shape and one supplier, not a second path a caller can take: nothing reaches the plane through it. Keep it required rather than optional, because an optional provider is a plane that silently runs unvalidated.

**Guards go IN the method, not in a chain before it.** The Registry's route table works because its steps are uniform and orderable — `steps: [connectionRateLimitGuard, turnstileGuard, forwardRaw]`. A Resources operation is not like that: `transaction` carries genuinely intricate logic, from ADR-005 eTag currency to per-op DAG checks across a batch to ADR-006 reference rewriting, and lifting its guard out of its body would make both halves harder to read. **What this buys is locality, not tabulation** — the answer is never in another file, and never on the far side of the mesh boundary.

**The node operation keeps the name `invite`** (Larry, 2026-09-21; `grant` was weighed and declined). It keys on an EMAIL, because a person new to Nebula has no `sub` to name — so it mints the membership that produces one, mails a real link, and kicks off a 7-day acceptance flow. `grant` would name only the durable half and would sit beside `dagTree.setPermission`, the `sub`-keyed grant that must already exist, putting the word on the wrong method.

⚠️ **This leaves two `invite`s on the client, and that is deliberate — do not "fix" it.** `client.invite(targetScope, …)` reaches the Registry facade and can confer `scopeAdmin`; `client.resources.invite(nodeId, …)` reaches the plane and never can (`auth.md` § *Grants in both planes* is the recipe both follow). They are told apart by the first argument's kind and the `resources.` prefix. [nebula-scope-moves-to-subdomain.md](nebula-scope-moves-to-subdomain.md)'s standing instruction to name `Galaxy.invite` explicitly means the plane one.

⚠️ **Self-guarding forces one consequence, and it is what sets the task's reach.** A method that derives its caller cannot also accept a `clientId`, because over the wire that argument is forgeable and the plane cannot tell an internal call from a remote one. **So every `do*` method loses its `clientId` / `subscriberBinding` parameters and derives them instead, and § *The surface, allocated* says which surface each method lands on.**

That table replaces an earlier rule keyed on *whose rows* a method touched, which fit one of its four stated members. `invite` carries no caller id and stays a door. The drains take no arguments at all, and their only production caller is the Star's ontology-install eviction — the Galaxy has none, since its chat ontology self-seeds from a platform constant and never installs a new version. They are internal because there is nothing to derive and a wire caller would drop every subscriber on the host, never because of a caller count. The reapers are continuation targets, which is a surface rather than a visibility, and `#private` is not even available to them: `ocan/execute.ts` dispatches by property lookup, so a `#` member is unreachable at runtime.

**The surface, allocated.** 
**The gate is what makes `public` on the plane mean CALLABLE FROM THE WIRE.** Today nothing returns the plane — the only gate is `dagTree()`, which returns the tree — so `public` there costs nothing and no method was ever chosen for a wire audience. A gate returning the plane would change that for all sixteen at once.

**So neither gate returns the plane. Each returns a narrow facade over it.** The door's members are the client's vocabulary and each derives the caller's own id; the results surface's members are the fire-back handlers. The plane below keeps one raw operation serving both, and the host reaches it directly — a host needs no gate for its own field.

```ts
#resources = new Resources(...)                            // the plane — the host calls it DIRECTLY
#door      = new ResourcesDoor(this.#resources)            // derives clientId from callChain[0]
#results   = new ResourcesResults(this.#resources)         // the fire-back handlers

@mesh() resources()  { return this.#door }
resourcesResults()   { return this.#results }
```

| Facade / plane | Member → the plane op it wraps |
|---|---|
| **`ResourcesDoor`** — `@mesh()` | `transaction` → `doTransaction` · `read` → `doRead` · `subscribe` → `doSubscribe` · `unsubscribe` → `removeSubscriber` · `subscribeQuery` → `doSubscribeQuery` · `unsubscribeQuery` → `removeQuerySubscriber` · `subscribeQuerySubscribers` → `doSubscribeQuerySubscribers` · `unsubscribeQuerySubscribers` → `removeQuerySubscriberListWatcher` · **`subscribeTree`** · `invite` · `dagTree` (getter) |
| **`ResourcesResults`** — no `@mesh()` | `onInviteResult` · `onBroadcastResult` → `removeSubscriber` · `onQueryBroadcastResult` → `removeQuerySubscriber` · `onQuerySubscriberListBroadcastResult` → `removeQuerySubscriberListWatcher` · **`onTreeBroadcastResult`** — reaping the merged row's tree kind |
| **Plane, reached by BOTH facades** | `removeSubscriber` · `removeQuerySubscriber` · `removeQuerySubscriberListWatcher`, plus the tree remover the merge folds into them — exposed by neither facade, so nothing on the wire supplies the id |
| **Plane, host-only** | `ensureResource` · `findCurrentByField` · `clearSubscribers` · `clearQuerySubscribers` · `clearWatchers` · `targetsForQuery` (`#private`, see below) |

**The `do*` prefix goes with the parameters, and the DOOR is what derives them.** ⚠️ Do not read this as the plane's methods losing their `clientId` argument — they keep it; the door supplies it, and that is the whole reason the plane can hold a forgeable-looking parameter safely.

⚠️ **`subscribeTree`'s own authorization reasoning needs a home.** Its JSDoc argues there is *intentionally no node-level read check* — a member may watch the tree because ADR-008 makes it visible to every member — and today it sits beside `@mesh() dagTree()`, which this task deletes. On the door that reasoning belongs at the merged registry's tree kind, next to the nullable `sub` that records the same fact.

⚠️ **`streamProgress` is NOT a results member, and putting it there would open a hole rather than close one.** It is a request-leg push: `protected`, no `onResult`, and `progress` + `replyTo` are caller-supplied, so behind a response-open accessor any passage-holder could inject arbitrary text into a shared chat attributed to someone else's live turn — and `replyTo`'s own JSDoc makes that attribution load-bearing against a hang. It is **host-only**, and because the plane has no `this.lmz` the transient push owes a `ResourceHostBridge` member, exactly as `fireInvite` does. ⇒ Then `targetsForQuery`'s only host caller, `Galaxy.queryTargets`, exists solely for `streamProgress`, so **`queryTargets` is deleted and `targetsForQuery` becomes `#private`** (`calibration.md` §2 — delete the problem).

**The third row is what the facades buy, and it is the tension in § *Design intent* dissolving rather than being paid.** `removeSubscriber(resourceId, clientId)` has two callers of opposite provenance — `unsubscribe`, where a client drops its OWN row and the id is derived, and the reaper, where the id belongs to a client already gone. Self-guarding cannot serve both: derive, and the reaper cannot name the dead; accept, and the parameter is forgeable. Keeping the raw op on an unreachable plane serves both, and *"its methods cover themselves"* becomes a claim about the FACADES, which is where it is true.

**Why not the two cheaper shapes.** Self-guarding the host-only six fails on five of them: `ensureResource`'s server-composed `actor` is the point of the method, `findCurrentByField` takes no node argument to check, and the three `clear*` take no arguments at all, so there is nothing to derive and a wire caller would drop every subscriber on the host. Pulling their callers inside fails on the layer map — the Galaxy's agent-message commit is host business logic, not a resource capability.

**What the extra facade buys back: the door's member list IS the audit's unit**, so the per-method classification the decorator grep used to force has a home a test reads off a prototype rather than a pattern over decorator lines.

**Load-bearing claims, stated so review can falsify them:**

  - **The reapers carry no host-specific work, so nothing holds them outside** (checked 2026-09-21). All three bodies are the same nine lines with one word changed: test the result for `ClientDisconnectedError`, take `clientInstanceName` off it, and call `removeSubscriber` / `removeQuerySubscriber` / `removeQuerySubscriberListWatcher` on the plane. No host state, no ontology, no config. ⚠️ Their grouping above is about WHOSE rows are reaped — the case that forced self-guarding — never about where the code lives; do not read it as a reason to keep them on the host. They move in with their names intact onto `ResourcesResults`, so the continuation becomes `this.ctn<Galaxy>().resourcesResults().onQueryBroadcastResult(queryHash)` — the same chaining `ctn<Star>().dagTree().setPermission(...)` already does today, through the accessor that carries no decorator.
    - **The arithmetic, since three different numbers have been written for it.** The Galaxy sheds three this way. The Star has FIVE `on*BroadcastResult` methods and only three are these — `onTreeBroadcastResult` reaps the tree channel, which the merge brings in — so it lands on `ResourcesResults` beside these three, and `subscribeTree` lands on the door, both carrying the same `callChain[0]` derivation as every other entry. `onReloadBroadcastResult` is deleted with its channel.
  - **They shed their `@mesh()` on the way in, and that closes a hole rather than opening one** (2026-09-21). ## The push path — what it stores, and what it rechecks

ℹ️ **The Profile was CUT from this file on 2026-09-22** (Larry) and now lives in [on-hold/nebula-profile-storage.md](on-hold/nebula-profile-storage.md). It is a consequence of the guard model rather than part of establishing it — the first host whose guard is not a grant — so it follows this file the way the Universe sibling does. **The injected authorizer went with it**, which is what keeps the plane at six constructor arguments here.

**Answered 2026-09-08 (Larry's two questions on the push path), because the phases turn on them:**

**Reading a permission costs no storage.** `DagTree` keeps the tree as a lazily-built state cache with an adjacency index over it, invalidated on every mutation, and `resolvePermission` walks that index in memory. So one `evaluatePermissions` call is a map walk, not a read. The cost objection against checking at push time is weaker than it looks, and the design question is which shape stores the least, not which runs least often.

**1. The stored `dominionOverHostAtSubscribe` bit exists because the push path has no token.** A Galaxy or Universe admin holds no grant in the host's tree — they reach it by dominion, which is a fact about their claims. Nobody is calling when a push goes out, so a bare grant evaluation would drop exactly those people. The bit is that remembered claim, and something like it is unavoidable while pushes are authorized at all.

⚠️ **What is wrong is not that the bit is stored, it is what the recheck's own comment implies.** `evaluatePermissions` takes the bit as a short-circuit, so for a dominion-holding subscriber the tree is never consulted and the verdict is the one frozen at subscribe. The recheck is live for grant holders and a replay for everyone else, while the comment presents it as uniformly live. By ADR-010's replication rule the bit is a copy of a mutable fact and owes a stated convergence mechanism; it has one — the client re-subscribes on reconnect, which re-derives the bit from the fresh token — but that is written only in `NebulaClient`'s resubscribe walk, on the other side of the wire from the column it converges. **State both at the column.**

**2. Keep the per-push recheck. It stores the least of the available shapes.** Three facts settle it. For grants it evaluates live and remembers nothing, so there is no second verdict to go stale. For queries it is not a freshness check at all — it computes the allowed and denied sets per subscriber, which is what lets a denied subscriber be told *which* nodes they lost rather than silently dropped ([ADR-008](../docs/adr/008-full-org-tree-visibility.md)), so it cannot move regardless. And the obvious alternative is worse: skipping the per-commit evaluation means materializing an allowed flag per row for the commit path to read, which is a second stored verdict beside the bit, and [ADR-013](../docs/adr/013-identity-profileid-resolution.md) calls a stored authorization verdict a security bug.

**There is no revocation window on the single-resource path, which was the worry.** A revoked grant is caught by the very next push, because `#broadcast` runs from the commit and evaluates live. Nothing is delivered in between, so nothing escapes. Queries differ, and not because they are safer: a permission change also fires an immediate rerun of every live query, and that exists to *disclose* the loss promptly under ADR-008, not to close a hole. ⚠️ Do not "fix" the single-resource path by adding it to that rerun — it would re-deliver on every DAG change to gain nothing, and wanting the two paths to look alike is what this note exists to stop.

**§ *Open question* is answered the same way: `registerQuerySubscriber`'s missing check is deliberate, and the merged registry keeps it missing.** Refusing at registration is what ADR-008 forbids — a subscriber must be able to learn the denied set, and a refused registration discloses nothing. So under this task's contract the method is not an exception to *every method guards itself*; its guard is authentication plus the delivery-time evaluation, and that is what the method must say. ⚠️ Write it as the guard it is. Recording it as *"always succeeds — no permission check"* is what made it read as a hole for two reviews running.
