# The guidance file tree — platform guidance in code, Galaxy guidance in the Workspace repo, both read every turn

**Status:** Pass-2 draft — phases written 2026-09-05 against the twice-reviewed design intent, awaiting `/review-task` Stage 2 — item ① of the run to the wipe in [nebula-pre-alpha.md](nebula-pre-alpha.md), **deploy-gated** (it only has to be in the bundle), and it **gates ② personas**. It delivers the tree with its platform and Galaxy layers, the always-on resource core, the docs and three seed skills behind a read tool, an edit tool, the chat history in the prompt, and one assembly for every turn, with every loop tool at the chat floor.

**Objective — every Studio turn reads a tree of guidance files with two owners: the platform layer we ship in code, and the Galaxy layer that lives in the user-developer's Workspace repo beside the app it describes.**

Five goals, in the order they matter:

1. **Guidance has one home, so the next file class lands in it instead of beside it.** The persona file is the first LLM-authored content; the vision and permissions files ship as seeded declarations with headings and are filled in as the app is built. Today each would invent its own storage and its own read path.
2. **The model knows how to build a data-bound app, so hand driving generates signal instead of re-finding the same gap.** The prompt teaches it nothing about resources today — no `store`, no `client`, no subscribe — and a hand-driven wishlist came back not using them at all (Larry, 2026-09-03).
3. **The user-developer's app carries its own guidance, and the LLM evolves it.** A Galaxy's `AGENTS.md` starts from a platform-written seed, and the end of a piece of work is where it changes — the loop this repo runs, pushed by the platform layer rather than left for the user-developer to discover ([docs/vision/_ai-security.md](../docs/vision/_ai-security.md) § *Level 2*).
4. **The Galaxy layer reads correctly to any agent, not only ours.** The Workspace is a git repo any agent may open — Claude Code on a clone, once a remote exists — so the file carries the cross-vendor name and layout.
5. **Shipping a platform-layer change costs a deploy and nothing more.** One authoritative copy, bundled at deploy, with no second copy to keep in sync; iterating it locally is regenerate-then-`wrangler dev`, with no deploy (§ *Storage is files in git*).

## Design intent, constraints, and future state

Four parts follow: the tree and the files in it; where each layer is stored and which tier it rides; what one turn assembles and in what order; who writes each layer and how the loop pushes itself.

**The tree, assembled.** What the model sees each round, in an order chosen so that what never changes comes first and what changes every turn comes last:

```
system layer, in order — stable first, so the cached prefix survives across rounds and turns
  1  TOOL_CONTRACT (the `tools` field rides beside it)   byte-identical until a deploy
  2  platform   .platform/AGENTS.md        ours — embedded at deploy
  3  [universe  .universe/AGENTS.md]       later — inserts here when built
  4  galaxy     AGENTS.md                  theirs — changes only when the model records something
  5  the chat history                      append-only: the human's words, the agent's reply, each turn's manifest
dynamic tail — changes most turns, so it comes last
  6  the ontology + current src/App.vue    src/ontology.d.ts leaves the system block (D7, re-derived for the cache)
  7  the request
```

**The Galaxy file, for real.** A user-developer's `AGENTS.md` a few turns into an app looks like this, and the model wrote every line of it:

```markdown
# Secret Santa — guidance for this app
- One group per event; everyone in a group sees the wishlists.
- Only the organizer sees who drew whom. Never show the draw to anyone else.
- Tone: warm and brief. No countdown timers, no gamification.
```

**The platform file, for real.** Six lines of the intended `.platform/AGENTS.md`, the file this task exists to produce; the rules that live in the prompt today move in beneath them:

```markdown
# Nebula — platform guidance, read every turn
- Resources are the only place user data lives. The ontology (src/ontology.d.ts) defines their
  shape, and `store` and `client` are how a component reaches them.
- Before any data-bound change, read .platform/docs/resources.md; for the store API in a
  component, .platform/docs/coding-your-ui.md.
- Skills (this list is generated from each skill's frontmatter):
  define-ontology — interview the user-developer and propose a shape: .platform/skills/define-ontology/SKILL.md
- Layers, in order: this file, then the app's AGENTS.md. The app's file adds; it never subtracts.
- The app declares itself in docs/vision.md, docs/personas.md and docs/permissions.md. Read them
  when they bear on the request; write them when the conversation settles something.
- When the user states a convention or corrects you, add the line to the app's AGENTS.md with
  edit_file, and say so in one sentence of your reply.
```

**The Workspace tree, laid out.** Two standard pieces and a handful of files we declare, at fixed paths the platform layer names:

```
/workspace
  AGENTS.md                 standard — always-on instructions for this app; the LLM writes it
  CLAUDE.md                 one line, `@AGENTS.md` — so the same tree reads in Claude Code
  .agents/skills/<name>/    standard — procedures, loaded on match (arrives with the skills work)
  docs/vision.md            ours — what the app is for; may link to sibling files
  docs/personas.md          ours — the cast, and how to re-establish it after a `.dev` wipe
  docs/permissions.md       ours — the permission model as decided, with a decisions table
  src/ontology.d.ts         ours — the data model; exists today
  .nebula/                  machine-owned rows; never guidance
  .platform/AGENTS.md       VIRTUAL — the platform layer, served from the bundle by the read tool
  .platform/docs/, skills/  VIRTUAL — the docs and seed skills, same mount
  .universe/AGENTS.md       VIRTUAL, later — the Universe layer, an upward read of the Universe DO
```

Three of those paths are not in the repo: `.platform/` and `.universe/` are mounts, not files (§ *A read tool* says how each resolves), and the write path refuses both prefixes. Everything else is the git repo the user-developer owns. The app's own `AGENTS.md` sits at the repo root, because that is where every agent that reads the standard looks for it, and its skills sit under `.agents/skills/`, the cross-client convention; `.claude/`-style directories hold nothing here.

**Standard pieces carry instructions and procedures; our files carry declarations.** `AGENTS.md` is always-on prose and a skill is a reusable procedure, which is the Agent Skills spec's own test for what belongs in one. Every Nebula app must also hold a set of declarations about that one app — its vision, its cast, its permission decisions, its data model — and the spec has no place for those, which is freeing. Each lives at a fixed path under `docs/`; the platform layer names the path and says when to write it; the seed creates each file with headings and a one-line "write this when", so an empty section reads as a gap rather than a missing file. This is the shape this repo already runs: the rules point at `docs/adr/` and `docs/vision/`, and a skill reads them.

| Declared file | Holds | How the standard pieces reach it |
|---|---|---|
| `docs/vision.md` | what the app is for, who uses it, tone and values — the master of a set, linking to siblings: Jennifer's five-file Gigi Kaizen spec becomes this file plus the four it links to | the platform `AGENTS.md` names it and tells the retro where to write; Studio reads it today, and it is the intended source for the end-user assistant's tone in [nebula-pre-alpha-fast-follow.md](nebula-pre-alpha-fast-follow.md) § *Item 2* — a second reader of one file, never a second store |
| `docs/personas.md` | the cast — § *Personas* | the third seed skill elicits it; ②'s executor re-establishes it after a `.dev` wipe |
| `docs/permissions.md` | which DAG shape each relationship got and why — a grant for limited sharing, a second parent for co-ownership — in prose plus a decisions table | the platform `AGENTS.md` points here; the vocabulary is [access-control.md](../website/docs/nebula/access-control.md) § *When to use which* |
| `src/ontology.d.ts` | the data model | pinned into the prompt today, unchanged |

**A permission model is decided, never specified.** The DAG lets the same intent be a grant or an edge, and which is right turns on whether either party may leave — a judgment per relationship, which no file format captures without becoming the DAG's own schema. So `docs/permissions.md` records decisions the way this repo's Decisions tables do: one row per relationship, the alternative rejected and why. That row is what stops the model re-proposing a grant where an edge was chosen. The model comes out of the personas conversation, so the third seed skill runs it: elicit the cast, ask "co-owner or limited share" per relationship, record the row, write the files, and hand the cast to ②'s executor as its last step. One row, from the Secret Santa app: *the organizer and a participant's wishlist — a grant, participant `write` on their own list and organizer `read`; co-ownership rejected, because the organizer must never edit a wish.*

**Personas: the tree gives the cast a home and the skill that elicits it; ② builds what runs it.** `docs/personas.md` is a numbered prose procedure — *Step 1: make Sally the `.dev` Star's stand-in founder: admin on the root node and scopeAdmin at `.dev`. Step 2: create the node `lists`. Step 3: add `example` beneath it. Step 4: grant Gerry admin on `example`.* — keyed on persona NAME and edited in place, because subs are re-minted by every wipe; every persona is synthetic, on an RFC-reserved dead domain (`@example.com`, `*.test`, `*.invalid`), never `@lumenize.io`. The seed carries a short template naming the four verbs any org-tree shape composes from — mint, node, edge, grant — with that worked example, the spec's "template for output format" pattern. This task ships the file, its template, the third seed skill that fills it, and the property of its run record: machine-owned under `.nebula/`, untracked, and wipe-independent, with the path decided alongside the executor that writes it. How the steps run — a typed `provision(plan)` the model translates the prose into, applied as a poster-confirmed step outside the loop, its deterministic executor, the impersonate-or-login choice, and where the first call that creates the `.dev` Star should come from — is ②'s design, recorded as its inputs in [nebula-pre-alpha.md](nebula-pre-alpha.md) § *② Personas*.

**Decisions tables, not ADRs.** A user-developer's durable decisions live as a `## Decisions` table inside the doc that owns the topic — `docs/permissions.md` first. The function is an ADR's, a decision beside its rejected alternative so nobody re-litigates it, without the numbered directory, the append-only discipline, or the status lifecycle — none of which a domain expert asked for, and all of which could only be advisory here. A numbered, statused record earns its place at the Universe tier, where governance wants an audit shape, and can arrive with that layer.

**Storage is files in git, in the repo that owns the layer.**
- **Platform layer:** `apps/nebula/platform/` (lean) — `AGENTS.md` and `skills/` — plus the docs read unchanged from `website/docs/nebula/`; one committed generator embeds both into the Worker bundle, with a drift test — the `scaffold-seed.ts` pattern, so nothing runs at dev time and the deploy is atomic by construction.
- **Local loop:** edit `apps/nebula/platform/`, run the generator, and `wrangler dev` picks it up — no deploy. When the offline replay bench un-parks (master plan § *Data-bound generation*) it imports this same embed.
- **Galaxy layer:** `AGENTS.md` at the Workspace root, tracked and committed like `src/App.vue`.
- **Measured cost (2026-09-03):** the docs add about 66 KiB gzipped (201 KiB raw) to a 519 KiB gzipped bundle against a 10 MB paid-plan limit, and `wrangler check startup` on the real bundle with the docs injected showed active startup CPU unchanged within run-to-run variance (an in-session measurement whose profiles were not kept, so the bundle size is the durable number) — a string constant does no work at import (`workflow.md` § *Startup cost is the criterion*).
- **History:** git holds the tree's; the agent Message's `codegen` record holds each turn's `sourceCommit`, the tree it read, and `appliedPaths`, the files it wrote.

**Each layer has one authoritative copy.** The platform layer lives in code because we are its only writer; a deploy ships it and nothing else holds a copy — [ADR-010](../docs/adr/010-random-opaque-keys.md)'s replication rule, where every second copy owes a convergence mechanism nobody wants to build. What expires this is a writer who is not us: a support engineer, or a per-customer override that must change without a deploy. That is a trigger to re-derive (§ *Future state* carries the shape a switch would take).

**The harness walks the tree, every turn.** Every turn reads the Galaxy file at turn start and places it after the platform layer. Reading per turn is what makes an edit take effect on the next message with nothing to restart; the platform layer is an import, so the read costs one VFS read per turn.

**Two tiers, and the boundary between them is what a model can be trusted to ask for.** The always-on layers are harness-injected and every turn pays for them, so only what changes behaviour on a typical turn belongs there. Everything else is read on request, which is the Agent Skills progressive-disclosure model: a catalog of names and descriptions costs about a hundred tokens each, a body loads on activation, bundled references load when the instructions call for them.

**On-demand loading has one failure mode: the model does not read what it does not know exists.** So the always-on core carries the three facts no reference can supply — resources are the only place user data lives; the ontology defines their shape and `store` and `client` reach them; any data-bound change means reading the resource reference first — and it names the file and the trigger, never a directory, which is the Agent Skills best-practices rule for on-demand loading.

**A read tool, and the four things it unlocks.** It is one addition to a three-tool surface and it carries this task's payload:

- **The docs on demand**, which is the whole delivery mechanism for goal 2.
- **Skill bodies**, the standard's own activation path for an agent whose model reads files.
- **Multi-file apps.** The harness pre-injects `src/App.vue` and the ontology and nothing else, so the first app to grow a `components/` directory is edited blind. That defect is latent today and this closes it.
- **The Galaxy's own `docs/`**, so `vision.md` and `permissions.md` are read when relevant rather than riding every turn.

Its shape is `read_file({ path })`, path-grained: it returns a whole file, so platform links point by path and anchors buy nothing this round (a `path#anchor` section read is § *Future state*'s answer to window pressure). It reuses `write_file`'s guard — `assertSafeRelPath`, so a model-chosen path cannot traverse — and the write side gains one derived rule: **only the user-owned tree is writable by the model's tools; every dot-directory except `.agents/` is reserved** — `.platform/` and `.universe/` are mounts, `.nebula/` is machine-owned, `.git/` is git's — which makes a user app shadowing a platform doc, or a `write_file` planting a registry row, structurally impossible rather than merely unlikely. This round `.platform/*` resolves to the embedded map and anything else to the Workspace; `read_file({ path: '.universe/AGENTS.md' })` returns `error: ".universe/ is reserved — no Universe layer exists yet"` until that layer lands, when it resolves to an upward read (§ *Future state*).

**Skills carry the conversation; docs carry the reference.** The spec's test is that a skill teaches how to approach a class of problems rather than what to produce for one instance. *"Interview the user-developer about what belongs on a wishlist item and propose a shape"* is a procedure and is a skill; `store.Todo.create(...)` is reference and is a doc. So the three seed skills are conversational — `define-ontology`, `wire-a-view`, `define-the-cast` (personas and permissions) — and each names the doc to read and the trigger for reading it. A skill is a directory with a `SKILL.md` whose head is three lines:

```markdown
---
name: define-ontology
description: Interview the user-developer about what their app stores and propose a typed shape. Use when a request names data the app does not yet hold.
---
```

The always-on catalog — one line per skill: name, description, location — is **generated from that frontmatter** by the same generator that embeds the tree, so a stale description cannot ship; the model activates a skill by reading its location. Backlog's wizard-style authoring row gains a pointer at `define-ontology` as its first rung (§ *Relationships*).

**Where each kind of guidance goes — one home per fact, and every other place points.** The tool contract is stated three times today, and two of the copies disagree on what to do after a timeout, so the placement rule is the mechanism that stops the next drift. The table is design intent here and moves into a path-scoped rule, `.claude/rules/studio-guidance.md`, as a phase deliverable — a rule rather than an ADR because it is a convention that must be in front of whoever edits these files at the moment they edit them, which is what `paths:` does and an ADR's always-loaded one-liner cannot. A procedure for changing guidance waits until the eval exists and "did this change help" is answerable; until then the steps are the generator, the drift test and the `/live` criteria, which `/build-task` already runs.

The self-correction message says "fix and call build again" and nothing else. The timeout line lives on the build report's failed step (row 2 of the table), in the description's wording: "simplify" is not a move the model can make without a build it can run in parts, and that build is a product gap — a backlog row Phase 7 adds, not prompt text.

**`publish` is renamed `preview` throughout the build tool** — `BuildArgs.preview`, the report step `preview: { refreshed, why }`, `decidePreview`, the tool description, the feedback message — because what the flag decides is whether the `.dev` preview reloads, and the product's *publish* is the shipped-tag `dist` served to tenant Stars, which is not built. The word is tool-internal today, so no user-facing copy moves; the tool-args bundle id bumps, as its comment already requires on any change.

**Cost is small, and the shape is the cheap one.** The system layer is byte-identical across every round of a turn, which is the ideal case for prefix caching, and Workers AI applies it by default. Measured from the vendor's own model pages, 2026-09-03:

| Model | Context | Input | Cached input |
|---|---|---|---|
| `@cf/moonshotai/kimi-k2.7-code` (today) | 262,144 | $0.95/M | $0.19/M |
| `@cf/zai-org/glm-5.3` | 1,048,576 | $1.40/M | $0.26/M |

Cached input is about five times cheaper on both, and the caching docs note an input must be large enough to cache at all — so today's roughly 500-token system layer is the case that caches worst. **Send `x-session-affinity` with this task**: it is one header on both lanes and it is what makes the per-turn hit rate real, keyed as the next passage says.

**The transcript is the session; the Galaxy file is the memory.** Coding agents send the whole conversation on every call, append-only, and rely on the prefix cache to make it affordable; when it nears the window they compact, replacing the history with a summary and re-injecting the stable instructions after it. Our turns are heavy — whole files and build reports — so the full transcript would outrun a 262k window in a long session. But the durable Message already stores each turn's manifest (`appliedPaths`, `rounds`, `stop`, the build findings, `sourceCommit`), and old file contents are noise once the current source is supplied fresh. So the history bundle is an exclusive projection: per message, its speaker — kind (agent or human) and a stable per-`sub` label with the display name where cheap, from `deriveParticipants` on the stamped `actingToken` — its `content`, and from `codegen` only `appliedPaths`, `rounds`, `stop`, `build.findings` and `sourceCommit` — never `toolCalls`, whose `write_file` args carry whole files, and never `thought`. The request bundle marks the current poster. The chat is four-party by construction, so a bundle of bare `content` could not tell the owner's convention from a coach's aside. A few hundred tokens a turn, twenty thousand after sixty. Real compaction waits for threads — a thread is a second `Chat` under the Galaxy; multi-chat is deferred with the management UI, per `DEFAULT_CHAT_ID`'s JSDoc — whose "pull the relevant context into a new thread" step is compaction by another name; a thread is then the session, and the Galaxy's `AGENTS.md` plus `docs/` is the memory across threads.

**Two rules keep the prefix stable.** The cache reuses the longest unchanged prefix, so the order in § *The tree, assembled* puts what never changes first and what changes every turn last; nothing non-deterministic rides the prefix — no timestamps, no reordered keys; and `x-session-affinity` is `{u}.{g}:main` — the Galaxy's `instanceName` plus a segment naming the conversation — because the header routes a request to the model instance holding the cached tensors ("prefix caching only works when a request routes to the same model instance"). How a thread is keyed when threads land is § *Future state*'s.

| Twenty thousand tokens of history, Kimi | Per round, uncached | Per round, cache hit |
|---|---|---|
| One round | $0.019 | $0.004 |
| Eight rounds | $0.15 | $0.03 |

Cost is not what to economize; the window is, which is why the compact representation matters more than the cache does.

**Full-file loss is answered by `edit_file`, not by a guard.** `write_file` saves complete contents, so a model adding one line to `AGENTS.md` re-emits the whole file and a dropped line leaves no signal. An `edit_file({ path, anchor, replacement })` tool — refusing an anchor that is absent or matches twice — can only change what it names, so the safe path becomes the cheap path, and the standing instruction picks it for existing files; the preference — edit an existing file, write a new one or a deliberate rewrite — lives in the two tools' descriptions, where mechanics live. Its failure is loud, an error the model sees and retries. The archived loop plan already names it as whole-file regeneration's successor, and it pays outside guidance too: a one-line change to a four-hundred-line `App.vue` emits a few lines instead of the file. Rejected alternatives are in § *Decisions*.

**One assembly, every turn; the model decides whether to act.** The loop already ends a turn that makes no tool call as `no-tool-calls` with the reply as the answer, which is exactly how a question is answered. So the answer fork is deleted, every turn gets every layer and the full tool set, and a question that turns out to need a one-line fix gets the fix, under the poster's authority and named in the reply. The property the fork asserted — a plain question starts zero containers — is dropped: a question may now cost one speculative start, and every warm still owes the turn's teardown — the `finally` that calls `#destroyBuildContainer()` around the codegen body, which every exit reaches (`no-tool-calls`, the round cap, a `mark_complete` without a build) — which the hint and the `write_file` warm both ride: at most one warm per turn, latched, and a teardown per warm. `chat-trigger.test.ts`'s T5 asserts the dropped property, zero warms on a plain question, and is retired for its successor.

The one job the classifier did that the model cannot is timing the container warm: its verdict fired before round one, hiding the roughly three-second cold start and mount behind ten to thirty seconds of generation. The structural replacement is the first `write_file` of round one, a certain predictor of a coming `build`, which hides only round two's short generation — a second or two of exposed latency. So the cheap call stays as a **warm hint only**: a wrong "yes" wastes one container start, a fraction of a cent; a wrong "no" costs the second or two, because the `write_file` warm fires regardless. A hint with a structural backstop is a different thing from a fork. Whether the hint earns its sub-second call is measurable, and Phase 6 measures it.

**Lower layers add to higher ones; the security floor is not in the prompt.** The platform layer states the order and that a lower layer adds to the layers above it. A token reaches what its claims allow, and nothing the model is told changes that ([docs/vision/auth.md](../docs/vision/auth.md) § *When Nebula is the actor*). What bounds an injected line is a rule the tool table is tested against: **no tool whose floor exceeds the chat floor joins the loop's surface** — an operation above it is a poster-confirmed step outside the loop, the rule the loop's header already has for install and wipe (`compileAndInstallOntology`, `resetDevData`, `setOntology` fire after the loop, human-gated) and the shape ADR-015 gives destructive restraint. A collaborator's line in `AGENTS.md` is injected on every later poster's turn, so per-turn guarding alone would let it steer the owner's turn toward what only the owner may do; under the rule, the most any line can reach is what every chat participant can reach anyway.

**Who writes each layer.** We write the platform layer, by deploy. For the rest, one rule: **a guidance layer's write floor is the write floor of the thing it describes.** The Galaxy layer sits in the app's source tree, so it takes source's floor — DAG `write` at the chat node, the door that let the message land — for every path, client and agent alike: a collaborator who can change `src/App.vue` can change the `AGENTS.md` beside it. The Universe layer describes an organisation's practices, so *editing takes dominion* stays verbatim there. The LLM is an intermediary that is good, not perfect, at refusing a bad edit; every write is a commit and the chat is visible, so the risk is low and accepted (Larry, 2026-09-04).

**The door is the guard.** A turn runs under the poster's own `callContext` — the commit path's JSDoc states it — and it exists only because a Message landed, which required DAG `write` at the chat node. So every poster who can start a turn holds the same floor, and a per-tool check under the same claims would re-prove the door on every call. What must hold instead is that no loop tool reaches above that floor, and that is a property of the tool table, not of the model: the model can call only what the table lists, and our code implements each entry. The proof is a test on the table, in the shape of Star's `@mesh`-surface freeze.

The loop's internal `this.writeSource()` is then the ordinary call it looks like — once the entry's own guard agrees with the door. Today it does not: `readSource`, `writeSource`, `buildNow` and `appendWorkspaceOntology` carry `requireDominionHere`, so a collaborator's turn writes and builds while their direct call is refused, and their Apply is refused outright. Each guard changes to `requireChatWrite`:

```ts
/** The chat floor — the check a Message create runs at the door. */
export function requireChatWrite(instance: Galaxy) {
  instance.dagTree().requirePermission(CHAT_NODE_ID, 'write');
}
```

A Galaxy admin passes it through the confined scope-admin bypass inside that same check, so nothing changes for the owner. `warmPreview` is deleted rather than changed: its JSDoc says the answer is immediate since the collapse, the Studio sets the iframe source before it fires, and today it is refused silently on every collaborator's load; the build reply keeps its delivery path. `setGalaxyConfig` and `ensureChat` keep dominion — neither is a source operation.

| Loop tool | Reaches | Floor |
|---|---|---|
| `read_file` | `readSource` — guard changes to `requireChatWrite` | chat: DAG `write` at the chat node |
| `edit_file`, `write_file` | `writeSource` — guard changes to `requireChatWrite` | chat |
| `build` — compile for feedback, bundle, refresh the `.dev` preview | `#buildAndAnnounce`, the body behind `buildNow` — whose guard changes to `requireChatWrite` | chat |
| `mark_complete` | none; it ends the turn | chat |
| *not loop tools:* the ontology Apply with its wipe bit (`appendWorkspaceOntology`, guard changes to `requireChatWrite`); `resetDevData` (dominion over `.dev`, which the Galaxy invite's co-mint gives every collaborator) | their own entries | poster-confirmed steps after the loop |

`auth.md` owes two sentences and a block: § *Why upward exists*' "a Galaxy admin evolves that Galaxy's guidance" becomes the source-floor rule above; its write-versus-propose sentence narrows to the Universe layer, where proposing still routes; and § *When Nebula is the actor* owes a *Today's code differs* block naming the dominion guards on the source entries until this build changes them.

**The retro: the platform layer pushes the loop as a standing instruction.** When a participant states a convention or corrects you — the history bundle says who — or you fix something non-obvious, read the app's `AGENTS.md`, add the line with `edit_file` where it fits — a convention near the top, a lesson where it belongs, no fixed section — and say so in one sentence of your reply. The transcript in the prompt is what lets the model see a correction in the turn it arrives, and the sentence in the reply — the reply is the model's own text, § *Context* — is what lets the user-developer see the file evolve, since Studio shows no files (goal 3). The signal only acceptance can provide — undo, abandon, feedback — feeds the platform's own scaffold evolution and is recorded with ③.

- ⚠️ Design consideration: if a writer who is not us ever needs to change the platform layer without a deploy, the switch is a platform-level DO holding the same repo shape on `@cloudflare/computer` — a switch, never a mirror.
- ⚠️ Design consideration: a `path#anchor` section read is the answer to window pressure when whole-page reads grow costly (`api-reference.md` is ~76 KB); platform links gain anchors only then.

## Phases

Seven phases, in executable order. Each is one commit that leaves the suite green and the running system consistent, and each carries the pass-1 criteria it proves. A criterion marked **Exploratory** watches the model: it ships as a capable-of-failing check plus a findings note and never gates a phase (master plan § *Data-bound generation*); its deterministic twin is the gate. Every phase that changes the loop or the Galaxy's mesh surface ends with the registry sweep, `drive.ts all` — `--fast` only when no scenario the phase touches needs a container (`live.md`'s sweep rule).

1. **Every source entry sits at the chat floor, and a collaborator's direct call agrees with their turn.** `requireChatWrite` lands in `galaxy.ts` beside the entries it guards, as § *The door is the guard* shows it; the guards on `readSource`, `writeSource`, `buildNow` and `appendWorkspaceOntology` change to it, and `buildNow` gains the option the loop's `build` passes — `{ publish }` today, renamed in Phase 3 — so the loop can reach the entry rather than the private body. One exported table, `LOOP_TOOL_ENTRIES`, maps each tool to the entry it reaches — `write_file → writeSource`, `build → buildNow`, the two Phase 3 adds later — and `runCodegenTurn` builds its deps from that table, so a tool cannot reach an entry the table does not name. `warmPreview` is deleted on the Galaxy, on `NebulaClient`, in the Studio's connect path and in the baseline test app's echo stand-in; `deliverPreviewReady` stays for the build reply. [nebula-data-plane-owns-its-guards.md](nebula-data-plane-owns-its-guards.md) § *Context*'s carried-over list is corrected here; `auth.md`'s edit waits for Phase 4, where guidance first exists.
   - **Success criteria (capable of failing):** (a) `galaxy-resource-surface.test.ts`: every entry `LOOP_TOOL_ENTRIES` names carries `requireChatWrite` (read through `getMeshGuard`); the dominion list is exactly `setGalaxyConfig` and `ensureChat`; neither `Galaxy.prototype` nor `NebulaClient.prototype` has `warmPreview`. (b) In-lane, the `confine-dag-plane.test.ts` shape: a `.dev`-scoped `scopeAdmin` token with a `write` grant at the chat node calls `writeSource` on the Galaxy and a commit lands; a token holding passage and no chat grant is refused with `PermissionDeniedError`. (c) `four-party-chat` gains a limb on Austen's `.dev` session: direct `readSource('src/App.vue')` returns the file, `writeSource` returns an oid, `buildNow()` returns a report, and `setGalaxyConfig` is refused with the message that begins "Admin access required" — matched, never a boolean. (d) `first-app-built` passes unchanged: a fresh Studio load renders the built preview with no cue, which is the deletion's witness, so this phase's sweep runs without `--fast`.
   - **Mutation note:** restore `requireDominionHere` on `writeSource` → (a), (b) and (c) red. Have the loop call `#buildAndAnnounce` directly instead of the table's entry → (a) still greens, so the table test also asserts the deps object's keys equal the table's tools; that second code path reds it. Drop the message match in (c) → a boundary refusal passes as a chat-floor refusal, the collapse `live.md` names.

   - **An interim, two phases long:** the prompt constant stays live until Phase 4 deletes it, so until then the rules exist in both places and the file is read by nothing.

3. **The model can read what it is told about and change one line of a file, and the write path refuses every reserved directory.** `read_file({ path })` resolves in one order: a `.platform/` path answers from `PLATFORM_FILES`, or an error naming the missing file; a `.universe/` path answers `error: ".universe/ is reserved — no Universe layer exists yet"`; anything else passes `assertSafeRelPath` and reads the Workspace through `readSource`. `edit_file({ path, anchor, replacement })` reads the file, counts the anchor, refuses zero or two-plus matches with an error and no write, and otherwise writes the replaced file through `writeSource`. Both writers refuse a path whose first segment starts with `.` unless it is `.agents`. `read_file` is exempt from the identical-call detector as `build` already is. `publish` becomes `preview` throughout — `BuildArgs`, the report step, `decidePreview`, the description, the feedback message — and `TOOL_ARGS_BUNDLE_ID` bumps.
   - **Also lands here:** tool descriptions carry the mechanics — `write_file` is for a new file or a deliberate rewrite, `edit_file` for a change, and `read_file` names `.platform/` and the catalog; the build report's failed container step carries the timeout line, and the feedback message says "fix and call build again" and nothing else; `LOOP_TOOL_ENTRIES` gains `read_file → readSource` and `edit_file → writeSource`.
   - **Success criteria (capable of failing):** (a) `codegen-loop.test.ts`: `write_file` and `edit_file` under `.platform/`, `.universe/`, `.nebula/` and `.git/` are rejected before any write, and `.agents/skills/x/SKILL.md` is accepted. (b) `read_file` of `.platform/docs/resources.md` returns the embedded page byte-for-byte; `read_file` of `.universe/AGENTS.md` returns the reserved-prefix error; a Workspace path returns the file. (c) `edit_file` with an anchor matching twice, or not at all, returns an error and the file is unchanged; a unique anchor changes only the matched span, every other byte identical. (d) Two consecutive identical `read_file` calls do not end the turn `loop-detected`. (e) No `publish` survives in the build tool path, and `{ preview: true }` refreshes the `.dev` preview; the typia validator rejects a `publish` key.
   - **Mutation note:** drop the dot-directory rule → (a) red, and a generated app could shadow a platform doc or plant a registry row. Remove the anchor count → (c)'s first match is edited silently. Restore a `publish` key on `BuildArgs` → (e) red; skip the bundle-id bump → the stale validator serves the old shape and (e) red.

## Non-goals

Each exclusion names its home, so nothing leaves by omission.

- **The Universe layer** — its mount is reserved and refused this round; the layer arrives with the Universe Workspace (§ *Future state*; [on-hold/nebula-skills.md](on-hold/nebula-skills.md) § *Future extension*).
- **Galaxy-authored skills under `.agents/skills/`** — the directory is named and reserved as writable; bodies wait for the skills work.
- **Threads and compaction** — a thread is a second `Chat`; multi-chat is deferred with the management UI (`DEFAULT_CHAT_ID`'s JSDoc); the thread affinity key is decided then (§ *Future state*).
- **A retrieval tool over the user-developer's codebase** — chunking, embeddings and Vectorize; paths in a catalog are enough at this size (§ *Future state*).
- **Splitting the platform layer into `rules/*.md`** — nothing in it is conditional yet (§ *Decisions*).
- **Un-hardwiring the discriminator's `respond`** — [nebula-pre-alpha-fast-follow.md](nebula-pre-alpha-fast-follow.md) § *Item 6*.
- **`report_finding`** — the placement table's Reporting row lands with ③'s tool ([nebula-pre-alpha.md](nebula-pre-alpha.md) § *③ Capture live*).
- **The persona executor, `provision(plan)`, and its record's path** — ②'s, with its inputs in [nebula-pre-alpha.md](nebula-pre-alpha.md) § *② Personas*.
- **A partial build** — the move the timeout line cannot ask for; the backlog row Phase 7 adds.
- **An LLM edition of the docs, or a transform of their outbound links** — shipped as-is (§ *Decisions*).
- **A per-customer platform override, a model swap, `path#anchor` reads, a git remote, commit author as poster** — each a design consideration in § *Future state*, none foreclosed.
