# Coding Style

- **Private members**: use the `#` prefix; the TS `private` keyword MUST NOT be used — `#` gives true runtime privacy, not just compile-time.
- **Type system**: TypeScript `interface`/`type` definitions are the single source of truth — a second schema language (Zod, TypeBox, JSON Schema) MUST NOT be introduced. Runtime validation at wire/persistence boundaries (e.g. Resources sent over the wire) MUST validate against those same TS types with `@lumenize/ts-runtime-parser-validator`. Background: [docs/adr/001-typescript-as-schema.md](../../docs/adr/001-typescript-as-schema.md).
- **Imports**: anything exported from a package's `index.ts` MUST be imported as `import { x } from '@lumenize/some-package'`. A relative import (`./file`) MAY be used **only** for an item in the *same* package that is *not* exported from its `index.ts`.
- **IDs**: use `crypto.randomUUID()` for unordered unique IDs; `ulidFactory({ monotonic: true })` from `ulid-workers` for ordered IDs. **`Date.now()` MUST NOT be used** for IDs or timestamps in Cloudflare — the clock doesn't advance within an invocation, so repeated calls return the same value (duplicate IDs).
- **Timestamps**: persisted/wire timestamps MUST be **ISO 8601 UTC ("Zulu") strings** (`new Date().toISOString()` → `2026-07-11T00:00:00.000Z`), stored as SQLite `TEXT`, compared as strings (lexical = chronological); end-of-time sentinel `9999-01-01T00:00:00.000Z`. **Epoch `number` MUST NOT be used.** Protocol fields keep their spec (JWT `exp`/`iat` = NumericDate epoch seconds; HTTP = RFC-1123). Background: [ADR-011](../../docs/adr/011-iso-timestamps.md); the clock-pinned-within-invocation caveat above applies regardless of encoding.
- **Optional over nullable**: `field?: T` SHOULD be preferred over `field: T | null`, especially in Resources/ontology types — Lumenize models "field absent = no value" (`{ name: 'a' }`, not `{ name: 'a', parent: null }`). `| null` SHOULD be kept only when "present-but-null" is semantically distinct from "absent", or when the code specifically exercises JSON-boundary behavior (`undefined` keys drop).
- **Guard naming — the verb is a CONTRACT, not a style.** ⚠️ **Symbols marked ⏳ are NOT YET IN SOURCE** — a rule citing a symbol nobody can grep is the exact harm it exists to prevent. Each names the task file that lands it; **delete the ⏳ when it does.** Two families exist and they **fail differently**, so the name has to say which:
  - **`require*` MUST throw** — `requireDominionHere`, `requirePassage`, `requirePermission`, all in source. This is the repo's incumbent spelling and the dominant-ecosystem one (Solidity's `require`, `assert`). **`enforce*` MUST NOT be used** — it was a one-member category whose verb implied a distinction it never carried, and it is now absent from the repo.
  - **A step that RETURNS a `Response` to refuse MUST take the `*Guard` suffix.** ⏳ `passageGuard` and `dominionOverScopeGuard` land with `tasks/nebula-registry-route-guards.md`. These are route-pipeline steps, and the contract is now **in source** — `Step` in `packages/nebula-auth/src/route-pipeline.ts`, returning `Promise<Response | Request | void>` or the bare union. A noun phrase is the right word form for a list entry, and Angular/NestJS guards set the precedent for returning rather than throwing. ⚠️ The runner does **not** catch a throw, so a step that throws answers no status of its own.
  - ⚠️ **Why this is load-bearing:** `nebula-auth`'s router catches everything and returns a blanket **500**, so a route step named `require…` — written by analogy with its throwing neighbour — returns `500 internal_error` where a `403` belongs. That defect has been written twice: once through a mis-cited hook convention, once through the name alone.
- **Security-verdict identifiers follow three tiers.** A **structural fact** gets a literal name (`isPlatformInstance`; ⏳ `isAtOrAbove` and ⏳ `isAtOrBelow` land with `tasks/nebula-passage-dominion-from-scope.md` — both, because the pair exists so no caller ever spells the upward arm with transposed arguments); a **verdict** gets its reserved word — `hasDominionOver` is the shared predicate in source, and ⏳ `hasPassage` lands with `tasks/nebula-passage-dominion-from-scope.md` (see [ADR-015](../../docs/adr/015-passage-and-dominion.md) § *Terminology*; note `reach` stays a **verb** and is never a noun for either verdict); **data** keeps its field name (`scopeAdmin`, `authScope`). ⚠️ **The tiers govern EVERY identifier, not only exported ones, and the locals are where the bugs come from** — a predicate renamed correctly, called by a guard still named for the bit, over a local still named for the old model, leaves the reader holding exactly the translation the rename was meant to delete. **A guard MUST take the name of the verdict it enforces, never of the claim field it reads; a local MUST take the name of what it holds, never of what it used to hold.** ⚠️ A verdict name SHOULD carry its object where the relation is two-place — `requireDominionHere` rather than `requireDominion`, because "require dominion" is one reading from *the bare bit is dominion*.
- **JSDoc — write for the distant caller, not the implementation.** The reader who benefits is the one calling from another file who won't open the body (and sees your JSDoc via LSP hover); whoever is editing the file already reads the code, so JSDoc there is near-redundant.
  - **Don't restate the signature.** Types already encode param names, types, optionality, and return shape, so `@param`/`@returns` MUST NOT echo them — it is redundant and drifts out of sync (when JSDoc contradicts the type, the type is believed, so stale JSDoc is worse than none). Type-only JSDoc MUST be omitted; let the signature speak.
  - **Document only what types can't express**: JSDoc SHOULD cover invariants/preconditions, units & formats, side effects, ownership/lifetime, throw/error behavior (esp. cross-boundary typed errors — see [durable-objects.md](durable-objects.md)), and concurrency/billing implications — plus the non-obvious *why*. One crisp sentence beats a paragraph. Cross-cutting conventions belong in `.claude/rules/`, and MUST NOT be repeated per symbol.
  - **When to bother**: any symbol read from a distance with a non-obvious contract — an exported API *or* a non-exported helper used widely across the package — SHOULD carry JSDoc. It SHOULD be skipped for purely-local symbols read inline; the code is right there.
  - **Examples**: inline examples MUST be ≤2 lines; anything longer MUST instead `@see` a `@check-example`-validated doc under `/website/docs/...` (JSDoc examples aren't validated, so they drift).
